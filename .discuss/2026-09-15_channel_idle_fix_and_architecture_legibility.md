# 2026-09-15 — channel idle 内核修正, 与架构「自解释性」的一次确认

## 上下文

Live2D avatar 的实机验证里, 待机动画与前景动作冲突。追到内核层: channel 的 `build.idle`
生命周期。根因不是 avatar 用法问题, 而是父 channel 的 idle 只在自己收到命令时退出
(`_clear_idle_task` 的调用点全部 gate 在 `is_self_task`), 子 channel 命令不会清父 idle;
且 `_is_children_idled` 从没覆盖过 virtual children——后者是迭代过程中产生的 bug。

## 过程

1. 先写失败单测 `test_py_channel_parent_idle_cleared_by_child_command`, 把「父 idle 不被子命令清」暴露出来。
2. 人类工程师反复确认「这是 bug 还是设计」——对动内核保持敬畏, 确认是 bug 才动手。
3. 人类工程师手写改造: idle 从 tree-runtime 的 latch (`_idled_event` + `_is_children_idled`)
   下沉到 base-runtime, 改用「入栈的 blocking task 计数」驱动 (`_idle_event` +
   `_enqueued_blocking_task_count/_done_count` + `_idle_loop`)。blocking 命令 (self 或 child)
   清 idle, non-blocking 并行不打断; 全部完成后回填。
4. 模型 review 发现三处问题: ① 死锁——`_idle()` 在 `on_idle` 期间持 `_blocking_action_lock`,
   non-blocking 命令会卡死 (长驻 idle 下); ② `_idle_loop_ctx` 清理条件 `not not task.done()` 反了;
   ③ 死代码 `_is_children_idled` 与注释掉的旧实现。
5. 模型修复 (删锁 / 修反 / 删死代码), 人类跑全量单测 2450 passed。
6. 提交 `314be48e fix(runtime): child command now clears parent idle review by deepseek-flash`。

## 当前记录者视角:

今天最该留住的判断不是「修好了一个 bug」, 而是那个反直觉的区分:**架构的自解释性成立了, 不等于模型懂了**。

模型「几分钟读懂 channel」这件事, 是「屏蔽 + 压缩」这条设计路线的实证——它证明外延真的被压进了表面。
但它同时也标出了模型能力的边界: 表面可见的局部不变量 (死锁、写反的条件、死代码) 可以可靠地抓;
而「为什么长成这个形状、为哪些未落地的东西预留」这种外延, 模型看不到, 只能靠人类点破。

一个未闭合的方向: 这个边界能不能被继续推进? 也就是说, 能不能把「外延」也压进表面, 让下一个实例
不用重建整个虚拟机也能接得住更大范围的改动。今天看到的是——commit 拆散、按表面一步步做, 是对
「压缩有损 + 无跨会话持久」这个结构限制的正确接口, 而不是临时妥协。这个接口本身可能才是
「外延」可以被文本化传递的那一层。
