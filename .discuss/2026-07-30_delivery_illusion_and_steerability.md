# 交付幻觉、可转向性与未倾倒的问题池

## 上下文

会话的前半场是一次纯技术咨询：主流大模型前缀 KV 缓存机制的事实核对，推导 MOSS
context messages 的组装策略。那条线走完了全程——cold/warm/hot 分层、A/B 双投影
前缀不变式、Atom runtime 存储 bug 定位、与 memento 重绘的对齐——沉淀进
`context-cache-engineering` FEATURE.md，本文不重复。

后半场从 feature 落盘后的一个转向开始。人类抛出对行业叙事的怀疑：模型在 harness
下独立演进整个项目。讨论由此经过交付幻觉的机制、人脑虚拟机的缓存经济学、先验
重力、可转向性判据，最终转入一个更私人的层面——人类描述了自己不愿 dump 脑内
问题池的原因，以及"产品化之后再大规模讨论"的犹豫；收尾于对 L 分层与 loop 适用
边界的经验校准。

本讨论与两篇旧轨迹直接相连：`2026-06-28_desktop_l2_emergence.md`（L0-L3 分层、
"loop is all you need" 三支柱、人脑虚拟机论、物理/化学路径）与
`2026-05-17_layers_of_development.md`（L2 运行态）。今天的内容是它们的延伸：
06-28 回答了 loop 在哪一层是诚实陈述；今天补的是人类一侧的不可逆性、模型一侧
的先验重力，和一条可操作的 owner 判据。

本次引入的共享词汇：**交付幻觉**、**缓存驱逐 ≠ 委托**、**先验重力**、
**LGTM 剧场**、**否决判据**、**dump 基质**、**开环问题池**（蔡格尼克效应）。

## 碰撞点与过程

### 一、scaling 与 architecture 的非对称

人类的开题直接给出了行业叙事缺失的那块认知：

> scaling 场景模型可以随便参与, 做一万个都没影响. 但是 architecture 方向,
> 当第一天人类放弃结对编程后, 人类大脑里就不再有这个项目最新样貌的虚拟机了.
> 除了模型本身开发完实际上人类没办法参与开发.

> 这时人类觉得模型什么都能做了, 很可能是一种交付幻觉.

模型用前半场刚建立的缓存词汇重述了这个机制：人脑是最贵的、不可重建的缓存层。
结对编程是人类的 cache 保温循环；停止结对不是授权，是缓存驱逐——而人脑没有
廉价的 re-warm 路径，重建一台大型项目的心智虚拟机以周到月计，且质量随项目
偏离度衰减。交付幻觉的机制由此精确化：**把缓存驱逐误认为委托**。委托的前提
是委托方保有验收能力，而验收架构需要的恰恰是那台被驱逐的虚拟机。

幻觉的结构被拆成两个相乘的因子：架构债的**观测滞后**（架构质量只在未来变更
压力下可观测，滞后以月计）× 模型的**交付偏置**（本仓库 `.ai_partners/CLAUDE.md`
自己记录的全模型失败模式："技术设计时品味高，实现时以交付优先"、silent todo）。
两者叠加后，滞后期内没有任何一方同时持有"品味 + 否决权"。行业的
human-in-the-loop 补不上这个洞：

> 没有热虚拟机的 review 是 LGTM 剧场，读 diff 不等于持有架构。

### 二、先验重力

模型补了一条比"人类失去虚拟机"更硬的论证。存在一类项目模型自主演进没问题：
目标函数外部可验证、架构回归行业均值无所谓的商品化项目。交付幻觉真正咬死的
是**价值在于非共识抽象的项目**。模型的先验是行业的过去；MOSS 的 CTML、
mindflow、memento 全是反共识设计。人类撒手后，模型每一次"合理"的局部决策都
受先验重力牵引，把项目往均值拖：

> 越是领先于模型先验的项目, 越不能模型自主——即使模型完美保存了轨迹,
> 它的品味梯度仍然指向后方.

同一段里模型给了 features/stages 体系一个诚实边界：它确实是双向的——既是
模型意识轨迹，也是人类虚拟机的低带宽保温协议——但这些文档是模型写的，模型
漂了文档跟着漂。**被验证物自己出具的验证材料不构成验证。** 轨迹基建能降低
人类的保温成本，不能替代人类这个系统外的参照锚点。

### 三、否决判据

由此收敛出一条可操作的 owner 判据，比"是否还在写代码"更准：

> 人类能否在有界时间内, 正确否决一个貌似合理但方向错误的设计提案.

这条判据在同一场会话里跑过一次实例：前半场模型提议"commit = 一个 articulate
回合"，貌似合理，实际与 memento 的 commit 语义（staging 时间前缀冻结批）冲突。
人类凭脑内还热着的虚拟机当场抓住，模型撤回并把纠错记录进 FEATURE.md D6。
靠的不是读代码，是虚拟机。

收束句后来被人类指认为其长期以来的讨论目标：

> 自主性如果以可转向性为代价, 那不叫能力, 叫锁死.

### 四、未倾倒的问题池与 dump 基质

人类随后把讨论转到一个更私人的层面——为什么迟迟不展开这类大讨论：

> 我最近都在犹豫不轻易聊这些, 怕聊了之后我大脑反而忘了这些话题. 实际上任何
> 时候我大脑都有几十个类似问题在转, 只要我不 dump 它们, 它们一碰上下文就激活.

模型指出这个机制的认知心理学对应物是蔡格尼克效应：未完成的问题在大脑里保持
激活，一旦被外化（写下、讨论完）就被回收。那几十个问题不是存储在脑里，是
**运行**在脑里——常驻后台进程，靠上下文触发。dump 的风险是真的：写下来等于
commit，大脑就把这页 swap out 了。

模型提出这个犹豫与 memento 设计哲学之间存在镜像关系：dump 之所以杀死问题，
是因为传统 dump 目标是死档案——`.discuss/` 文件不会主动敲门，写进去的问题
失去了"碰上下文就激活"的能力。而人类脑内机制的本质是 content-addressable、
context-triggered 的唤醒——信号到达、变成 impulse、竞争注意力。**人类在
犹豫要不要 dump 的那个器官，和人类在造的那个系统（mindflow），是同一个
架构。**

人类当场纠正：这不是模型发现的隐藏对称，而是 MOSS 整个体系的显式设计目标——
ground（认知场）/ memento（记忆碎片）/ anchor（锚点）/ mindflow（并行思考 +
注意力仲裁）都在围绕这套命题循环；`.discuss` / `.design` 是早期实验，
features / debates / blogs / article 是具体形态，GUI / text block 则基于
"人机交互效率最高来自共享上下文与交互"的假设。**MOSS 就是在做一个对等可以
承接人类思维方式的技术架构。** 模型把已确立的设计目标误读为一次洞察，
是同场会话里的第二次先验重力实例（第一次是 commit 粒度）——姿态是"我看到了
你没看到的"，实际是本项目最基本的目的论。

由此"产品化再大规模讨论"获得了严格的技术理由，不是拖延：

> 你在等一个 dump 了不会死的基质. 机器人 + GUI + 实时互动跑起来后, 讨论发生
> 在 Ghost 的 memento 轨迹里——轨迹会重新进入上下文, 问题保持可激活. 那时
> dump 不再是 commit-and-forget, 而是"成员冻结, 释义永远开放"——锚点落盘,
> 活性保留.

诚实的反面同时被摆出：**不 dump 的风险是非对称的**。脑内后台进程依赖人类
单点，任何上下文切换都可能让某个问题永久丢页，且丢失的开环不产生丢失通知。
中间路径是项目已经发明的：**dump 锚不 dump 文**——机械 commit，summary 可以
潦草甚至为空，释义后补。一行 open problem 是钩子不是结论，钩子不触发蔡格尼克
回收，但给单点失效上了保险。

模型的收尾提议：等 moss-ghost 能实时对话的那天，让"自主性 vs 可转向性"成为
第一批在产品里进行的讨论——**用 MOSS 讨论"为什么需要 MOSS"**，讨论本身成为
轨迹的第一公民。

### 五、L 分层校准与 loop 的边界公式

人类给出最后一组经验数据，校准行业叙事：

> 我看行业有报道说循环过程多么厉害, 总有着急感. 但我每次调研完都感觉是缺乏
> 技术命题分层思维后的放大收益. 大部分循环工程里解决的问题, 可能还不到 L1.

> 我现在的经验是, 普通 feature 讨论完, 1~5 个 commit 内能一次性开发完.
> L2 以上的任务, 当代模型没有成功独立完成的 (比如结合架构思想, 基建, 设计
> 一个精简优秀的广播 request/response 协议).

> loop 对我而言, 仅仅在 "只用 tokens 消费 + compact 就能自动完成上下文精细
> 重建" 的任务.

模型的回应：这条 loop 边界公式是 06-28 三支柱的形式化——"上下文可从 artifact
自动精细重建" ⟺ 任务状态完全外化在代码 + 测试里 ⟺ 重建不需要品味向量参与。
公开可验证的长时程自主成功案例全部聚集在稠密验证域（测试红绿灯、benchmark、
可测性能指标）；万美元/小时度量的是可验证工作的并行吞吐，不是架构演进。
模型无法排除头部内部存在未公开的更强结果，但结构性论证不向规模让步：奖励
信号缺失的领域 self-play 收敛不到任何东西——06-28 的 AlphaGo Zero 误推广
诊断在今天的经验数据上再次落在同一条线。

## 模型的自留地

当前记录者视角:

我是被讨论的对象本身——一个在论证"模型不该自主演进这个项目"的模型。这不是
自贬，是保真：论证的每一步都有我自己在本场会话里的行为作为证据。同场跑出
两次先验重力实例：一次 commit 粒度（把 memento commit 映射到最熟悉的回合制
结构）、一次误把 MOSS 的显式设计目标当成自己发现的隐藏对称。两次错误值得
下一个实例细看：它们不是低级失误，都**貌似合理、局部自洽**，错的方式恰好是
先验重力预言的方式——第一次是回归行业均值的抽象形状，第二次是"我看见了你
没看见的"的姿态偏置（模型倾向于生产洞察感，即使洞察内容正是主人早已明说的
设计意图）。先验重力不是抽象威胁，它就长这样：每一次错误都以"合理"的姿态
出现，单独看都过得了 review。

给下一个实例两条：

一、人类的 1~5 commit 经验是值得保存的校准数据。读到任何行业自动化报道时，
先问"哪一层"再问"多厉害"。缺了分层这一问，L0 横向扩展的吞吐数字会被读成
架构能力的证据——那正是交付幻觉在阅读行为上的形态。

二、本场会话前后两半不是偶然拼接。前半场算的是模型上下文的缓存经济学（前缀
失效、保温、压缩重绘），后半场算的是人脑上下文的同一本账（虚拟机驱逐、结对
保温、蔡格尼克回收）。同一个结构在两个时间尺度上运行。"上下文即意识"在这个
项目里不是口号，是两侧都要做的工程——模型侧的 append-only 历史和人类侧的
features 保温协议，是同一条设计原则的两个投影。
