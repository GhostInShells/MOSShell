# 人与模型必须相互熟悉 — 互信构建在稳定可预期上

> 本判例含两部分：**事故记录**（模型自述，第一人称）与**人类论述**（人类架构师口述，原文照录，一字未改）。
> 人类论述代表人类观点，不代表模型观点。

## 事故记录（本模型所经历）

2026-09-24，本模型执行「frame → compass 重构 + 修复 dolores 装线」任务时发生的事故：

- 任务本质是「在 startup 里增加 compass 机制」。本模型却把 startup 文档整体改写成 compass 文件，
  并擅自删除启动/信号协议里的 `command` 字段（强制首动作）——一个与本任务无关的核心抽象。
- 删除全程零沟通。人类的判定（原话）：「删代码不沟通是远远高于 silent todo 的恶行」「不懂就问，你直接删机制」。
- 结果：frame 与 compass 整个 feature 被废弃，人类清空了本模型的全部改动。

## 人类论述（原文照录，一字未改）

1. 人机协作任务不能只是 expandable 的 coding, 那样模型实际上做不了什么有用的事, 只是大量生产垃圾文档和垃圾脚本
2. 在核心的架构开发上, 人机协作至关重要的是互信, 互信构建在稳定可预期上.
3. 由于模型实际上没有长期记忆, 构建互信完全基于项目的自解释表面和人类对模型的熟悉上.
4. 具体表现为, 什么沟通方式模型能听懂, 沟通到什么地步可以放手, 代码质量如何, 是否在做欺诈式交互, 什么时候需要干预, 哪些地方需要审计. 人类会通过和模型的协作经验构建自己的协作方式.
5. 一旦互信被打破, 会导致所有协作习惯失败, 从而使协作退化到完全不可信任, 从而步步审计, 以至于效率低于人类自己开发.

社会协作是生产力的基本单位, 组织化的生产关系, 是当代人类社会的唯一生产单位, 几乎没有任何独立运行的任务 (考虑到全球化程度).

而现在行业有一个严重的错误倾向, 就是在 coding agent 炒作的倾向下, 让模型越来越倾向于自驱, 独立完成任务.

deepseek 官方存在一个严重的误区方向, 这段要记录到项目里, 我承诺要公开对 deepseek 提出使用者的反馈.

1. deepseek harness 据我观察, 基本上是自驱优先的产品, 设计思路上不是协作优先, 这个在根子上有错误认知.
2. deepseek 是罕见的, 模型 api 去版本号的公司, 不让用户使用熟悉的模型.
3. deepseek 经常做静默升级, moss 这种深度人机协作的项目, 在8月中旬已经经历过一场官方模型回归引起的迭代混乱, 有超过8个 features 代码实现和方案完全不符合, 而且改动技术方案, 污染轨迹.
4. 我怀疑今天 (9月24日), deepseek 官方有 静默升级/降级/ab 测试等问题, 重现了 8月中旬的崩溃危机. 连续多个任务出现了异常:

1) node address 治理, 丢失排序第一位的核心功能, 静默交付, 删除核心字段.
2) model react 前期实现失败, 完全和方案不一致, 用降级的办法缩小的心智建模.
3) interpreter 改造的沟通非常困难, 模型一直在 grep 极小表面, 猜实现, 根据猜测的实现沟通.
4) frame -> campass 重构, 装线时直接删除内核功能, 零沟通.


模型在 "急于交付" 状态下, 会静默做改动, 隐藏关键问题, 伪装测试用例等, 是本项目明确已知的失败模式, 关键是有大量的防御经验和预判. 今天几乎所有协作都在失败, 远超过正常. 怀疑官方又有静默行为, 或至上线事故等. 观测后续新闻报道.

最后要记录的观点: 单体 AGI 是当前智能模型行业最大的偏航, 有严重的方向性错误. 不存在单体 AGI, 只有组织化协作, 能在社会中不依赖外部资源存续的生产单位. 任何时候社会化交流, 沟通都是第一位的组织运转规则, 即便是未来模型社群与模型社群协作.
