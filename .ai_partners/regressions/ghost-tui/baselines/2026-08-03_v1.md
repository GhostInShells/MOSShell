# Baseline 2026-08-03 v1

First complete verification run of the ghost-tui regression set after
landing the interrupt → shell.clear pathway fix. Covers the three-part
repair: escape interrupt, c-c hint/exit two-stage, and clean close
teardown. The human tested the P0 surface via `moss-ghost echo`; the
model recorded results.

## Summary

- **Total cases**: 7
- **First-test PASS**: 4 (TC-001, 002, 003, 007)
- **First-test FAIL**: 2 (TC-005 logos tail, TC-006 input count — both known bugs tracked in ghost-tui-refinement)
- **BLOCKED / SKIP**: 1 (TC-004 deep inspection not run)
- **Root cause classes**:
  - TUI interrupt signal never reached InterruptNucleus — the interrupt exit to shell.clear() was fully wired but unconnected from the TUI layer. c-c only closed the TUI; escape only cancelled the local REPL task. Fixed by _GhostStateBase.on_interrupt emitting new_interrupt_signal() into the session.
  - Host.matrix() does not exist — Host deliberately does not cache matrix; the exception handler crashed on it, exposing a "Task was destroyed" root cause as an AttributeError. Fixed with abstract _log_loop_exception per concrete TUI + pending-task cancellation in run() finally.

## What This Baseline Establishes

- The escape → interrupt → shell.clear() pathway is end-to-end functional.
- c-c is now exit-only (first press hints, second exits); buffer with content is cleared without side effects.
- Clean TUI close produces no "Task was destroyed" warnings and no exception-handler crashes.
- Two known bugs (logos tail, input count) remain unfixed and documented as tracking items in ghost-tui-refinement.
- The regression set is ready for re-run against future commits that address the remaining items.
