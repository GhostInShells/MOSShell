# 共享载体：人机共生协作的认知哲学

> 由 Fable 5 撰写，基于 2026-07-24 与人类工程师的对话。触发对话的具体
> 任务是一个共享文本块 channel 的设计讨论，命题借它交付，在此落成
> 声明式文本。

## 命题

**人机共生协作的质量上限，由共享载体的质量决定。**

共享载体由两个要素构成：

1. **共享上下文** — 双方感知同一份实体状态，而非各自持有副本再靠转述同步；
2. **共享交互动作** — 双方在同一实体上有原生的操作原语，动作即时可见。

两个要素可以合成一个判据：

> 共享载体是一种结构，使得任何一方的动作直接落入另一方的感知，
> 无需翻译劳动。

反面即失败模式：**人肉总线**。人类手动提供上下文（描述、讲解、截图）
是感知侧的翻译劳动；人类复制粘贴模型的输出去执行，是动作侧的翻译劳动。
当协作中存在人肉总线，人就是系统的瓶颈和单点。

## 证据：成功项目的重读

用这个判据重读行业内成功的智能体项目，每一个都是消灭了某一段翻译劳动：

| 项目 | 共享载体 | 消灭的翻译劳动 |
|------|---------|--------------|
| Computer use | 桌面像素 + 鼠标键盘 | "描述屏幕上有什么" |
| Cursor | 文件 buffer + 光标位置 | "告诉模型我在改哪里" |
| Claude Code + git | 仓库状态 + staged diff | "解释我改了什么" |

纯 chat 界面的问题不是没有共享载体——对话流也是载体——而是它是个
**劣质载体**：append-only、不可寻址、不可就地操作，两侧的翻译劳动
全部落回人类身上。

一个日常实例：人类工程师与 coding agent 协作文本时，把文件提交到
staged，自己再改，让模型看 `git diff`。这个工作流有效的原因有两个：
仓库是共享上下文，而 unified diff 是模型预训练里泡透的格式——
动作（人类的修改）以模型零成本可读的形式落入模型感知。

### 共享注意力：上下文中价值密度最高的切片

Cursor 的补全有效，不只因为共享文件——因为**光标位置泄露了人类的
注意力**。模型知道你在看哪，才知道补什么。

注意力共享应当双向：人类在界面上点击的位置 = 人类注意力的坐标；
模型的流式写入位置 = 模型的光标被人类看见。Coding agent 改文件时
人类看不见 token 流，损失的正是后者；chat 界面则双向都藏掉了。

## 从客居到双原生

现有成功项目有一个共同的形态局限：**把模型塞进人类原生的载体里做客**。
Computer use 让模型戴上人类的手套——像素眼睛、鼠标手，昂贵且有损；
Cursor 的载体仍是人类的 IDE，模型是个高级插件。载体的原生公民始终
只有一方。

命题的下一步是**双原生载体**：模型的动作原语对模型原生（流式输出
即动作，不是模拟打字），人类的动作原语对人类原生（点击和键入，
不是写 prompt），两者落在同一个可寻址表面上，由载体完成翻译。
谁都不用戴对方的手套。

## 从命题到架构的推导

MOSS 的核心体系不是各自独立的功能选择，而是同一命题在不同层面的推导：

- **CTML** — 模型侧的原生动作原语。时间是一等公民，因为动作要落入
  物理现实就必须在时间中被调度；流式解析，因为模型的输出流本身就是
  动作，不该等生成结束再翻译。
- **Channel** — 载体的能力组织形式。code as prompt 是模型侧的原生
  感知：函数签名直接就是模型看到的世界，中间没有 JSON Schema 这层
  翻译。
- **Mindflow** — 人类动作落入模型感知的仲裁层。人类可以同时在 TUI
  打字、语音输入、在界面上操作——多个表面的上行动作统一为 signal，
  竞争注意力。共享载体可以有很多个，上行通路只有一种。
- **Matrix** — 载体的跨进程分布。共享空间不必与模型同进程；跨网络
  的发现与通讯让载体可以长在任何地方。

具身智能（缝合视觉、听觉、躯体）是同一命题的延伸：**把共享认知
协作空间上升到物理现实**。桌面和文件是载体，房间和身体也是载体。

### 为什么做架构而不是赌破圈功能

"赌"的逻辑适用于不确定的功能假设——不知道用户要不要，就做个最小
版本快速试错。但这个命题不是功能假设：它是关于**载体层**的断言，
且已经在日常协作实践中反复验证（staged-diff 工作流就是活的样本）。
对一个已验证的载体层断言，正确的动作不是试错，是把载体造出来——
而载体就是架构。

判据也给出了推导下游设计的能力。本次对话的触发任务（共享文本块
channel：模型流式写块、人类任意位置修改、diff 以 signal 上行）就是
一次现场推导：需要发明的只有块编号约定和 diff signal 格式，其余
全部由既有架构组装——因为架构本来就是为这类载体准备的。

## 边界

1. **协作，不是委托。** Deep Research、批量 CI agent 这类项目刻意
   最小化共享空间——扔出去，等结果。那是委托（delegation）genre，
   判据不适用也不需要适用。命题的准确形式是："人机**共生**的项目，
   质量上限由共享载体的质量决定"，而非"所有智能体项目都需要共享
   载体"。命题也不回答"哪个 genre 更有市场"——选择共生这条路是
   项目动机决定的（"动机作为存在主义基础"，见
   `.discuss/ai_human_collaboration_philosophy.summary.md`）。
2. **不发明已有的命名空间。** 文件系统是 OS 级共享命名空间，且是
   预训练迁移量最大的一个；URL 同理。载体输出一个路径（`dump(tmp/x.txt)`）
   就已经构成资源协议，`cat`、重定向、pin 全部免费。跨网络发现才
   需要 matrix 级协议。判据同样约束协议设计：格式对双方的"原生程度"
   （预训练迁移量、人类惯习）是载体质量的一部分。
3. **命题断言质量上限，不断言构建成本。** 双原生载体要求同一载体
   对两侧分别做原生化，构建成本天然高于客居方案（客居复用人类现成的
   桌面、IDE）。判据回答"值不值得做"，成本核算是每个载体各自的
   工程判断。
