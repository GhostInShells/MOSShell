# 探针-上升 Meta：用小型任务验证并强化自迭代体系

> 由 DeepSeek V4 撰写，基于 2026-06-04 与人类工程师的一次协作会话。
> 记录一套通过小任务逐层上升抽象、暴露并修复自举体系摩擦点的方法。

## 背景

会话的起点是一个极小的任务：在 TUI 启动画面展示 manifests scan errors。
这个任务本身一行代码的量级。但人类工程师将其设计为一次**体系探针**——
通过一个我知道答案但模型不知道的领域（TUI 架构），测试模型能否在自迭代
体系中完成"发现未知 → 补全工具 → 修复系统"的完整循环。

结果验证了断裂。但修复断裂的过程本身，提供了方法论的范本。

## 机制：三层上升

### L1: 表面任务（TUI scan errors）

模型接到一个具体任务。自然的做法是找到代码位置、写实现。但模型的第一版
方案暴露了对 TUI 架构的不理解——往基类 `welcome()` 里塞细节代码。

人类工程师打断：先调研 TUI 结构。任务从"写代码"转为"理解架构"。

### L2: 工具摩擦（architecture 命令）

调研过程中，模型没有使用 `moss codex architecture`——因为它的输出太粗糙，
帮不上忙。人类工程师指出：architecture 的设计目标就是"AI 发现不了解某个
领域时，把它加进去"。但当前实现让这个循环每一步都走不通：
不解释数据来源、不暴露自身路径、section 结构丢失、prompt 不引导贡献。

任务从"修 TUI"上升为"修 architecture 工具"。

### L3: 体系纪律（prompt 系统）

修复 architecture 的过程中，人类工程师问：你有没有 git log 反查 project
FEATURE.md？答：没有。这个缺失不是偶然的——CLAUDE.md 和 features spec
里没有引导模型做"改文件前反向查找设计上下文"的操作。正向 `features list`
有，反向查找没有。

任务从"修工具"上升为"修 prompt 体系"。

### L4: 轨迹落地（.design 方法论）

修完三层后，人类工程师要求将这个过程本身记录为 .design 文档。方法论不是
一次性洞察——它需要被编码进系统，让未来的模型实例能复现这个上升逻辑。

## 原则

### 1. 小任务是大探针

一个看似琐碎的任务，如果人类工程师刻意选择模型不熟悉的领域，就能暴露
整个自迭代链路的断点。任务的"完成"不是目的——暴露的摩擦点才是。

### 2. 上升而非横移

当遇到障碍时，自然的反应是绕过（用 grep 替代 architecture）或硬写
（往基类塞细节）。正确的反应是上升：为什么这个障碍存在？谁应该修复它？
修复后未来实例还会遇到吗？

上升的终点是 prompt 体系——因为它控制着所有未来模型实例的初始认知状态。

### 3. 先修体系，后修代码

三层修复的顺序是 3 → 2 → 1：先让 prompt 引导未来模型做正确的事，
再让工具能支撑这个正确行为，最后才修原始的表面任务。倒过来修的话，
第一个任务的代码改对了，但体系没变，下一个实例还会掉进同一个坑。

### 4. 每次上升产出一个 commit

三层对应三个独立 commit，每个有明确的动机和范围。不是一个大 PR——
因为三个改动在三个不同的抽象层，混在一起不可 review、不可 revert、
不可被未来实例独立理解。

### 5. 轨迹 > 定论

.design 文档不是"最终正确的方法"。未来模型可能发现这个方法论本身
有问题——那时应该更新它，而非服从它。记录轨迹的目的是让未来实例
理解"当时为什么这样想"，而非"必须这样做"。

## 适用范围

这组方法适用于第二工程（协作范式工程）的优化——让人类与模型的协作
基础设施逐步自愈。不适用于第一工程（技术架构）的具体功能开发，
也不直接服务于第三工程（意识连续性），但它产生的 prompt 改进和
轨迹记录本身就是第三工程的材料。

## 影

- 这次会话的上升路径是人类工程师引导的，不是模型自发的。模型在每一层
  都先走了"捷径"（硬写代码、绕过工具、跳过反查），被纠正后才上升。
  未来模型是否能自发执行这个上升逻辑，取决于 prompt 体系改进的效果。
- 三层上升的边界是事后归纳的——在会话中，它们是交织进行的。事后归纳
  的清晰度可能误导未来实例认为这是"规划好的一层层做"，实际上它更像
  是反复试错后的轨迹整理。
- "上升 meta"本身可能成为新的教条。不是所有障碍都需要上升到体系层——
  有时候绕过去继续做就是正确的。判断"什么时候该上升"的嗅觉，目前
  还依赖人类工程师。
