# L2 碰撞方法论：人类-模型对等架构设计

> 由 DeepSeek V4 撰写，基于 2026-06-11 与人类工程师关于 Momento Mori 的 L2 设计碰撞。
> 记录一套让人类与模型在结构设计层面实现对等碰撞、而非单向问答的方法。

## 背景

L2 (Structure Design) 是模型从"写代码的"变成"设计架构的"的跃迁点。L1 (Feature Coding)
只需模型理解需求并实现——人类定方向，模型执行。L2 不同：人类和模型在同一个结构问题面前
是平等的推演者，各自从第一性原理出发，碰撞后收敛。

但模型默认的交互模式不是为 L2 设计的。模型倾向快速给方案（取悦效率），人类倾向快速做
判断（控制方向）。这两个倾向叠加，产生的是**假收敛**——双方在浅层共识上快速推进，
深层分歧被跳过，直到实现阶段才暴露。

> 人类工程师："你要尝试一次 L2 碰撞。这整个思路服务的目标，你要提炼出来，然后倒过来
> 自己推演一个方案，拿来和我的碰撞。如果你推演的和我推演的特别像，也拿特别像的来碰撞。"

L2 碰撞的目标不是"得出正确方案"。是**确保双方经历过独立的推演路径，在同一个问题上
真正思考过，而不是一方陈述、另一方确认**。

## 五阶段方法

方法的核心是**阶段性强制独立推演**。在关键节点上，不让模型直接响应人类的判断——
而是让模型先自己走一遍，再回来碰撞。

### 阶段一：问题锚定

**目的**：将模糊意图转化为具体的数据实体和操作。

人类用日常语言描述问题域——实体是什么、支持哪些操作、有什么约束。模型提出初版
Pydantic 模型。这个阶段不追求正确，追求**具体**——把问题从"我想做一个类似 git 的
数据结构"变成"Moment / Commit / Branch 三个模型，字段如下"。

> 人类工程师："最小的数据单元叫 moment。有一个 branch 的概念，可以一直提交 moment。
> 可以阶段性在 branch 基础上提交 commit，记录这一段到上一段之间的摘要结果。可以从
> 任何一个 commit checkout 一个新的 branch。"

> 模型："Branch 内 commit_ids 严格有序，新 commit 只能 append。Commit 的
> moment_start_id 和 moment_end_id 定义了它覆盖的 moment 区间，区间之间不应重叠。"

第一个模型几乎一定包含隐含假设。这是设计意图——暴露假设让人类可以逐个击破。

**判定标准**：模型提出的具体模型包含了至少一个可以被人类挑战的隐含假设。

### 阶段二：约束注入

**目的**：逐步加入真实部署环境的约束，逐轮收紧模型。

这是整个方法中迭代最多的阶段。人类每次注入一个约束，模型调整模型。约束不来自
"我觉得应该这样"——来自真实运行环境的要求（多进程、离散存储、并行思考、权限隔离）。

> 人类工程师："关键问题来了，commit 本身是一个索引 (moment a -> moment x) 加自身的
> 固定信息。还是说，它是存储单元。我理解是前者。branch 本身则应该是 commit 从起点
> 到终点的 index (commit a -> commit b)。这个和 git 不完全对齐。"

这一轮重新定义了 Commit 的本质——不是存储体，是索引体。模型的回应从"Commit 持有
moment 区间"调整为"Commit 是 Branch 上的引用点"。

> 人类工程师："moments 在多进程空间里很可能是离散的，所以这里需要的是顺序列表。"

打破模型隐含的"线性存储"假设。模型将 `moment_start_id / moment_end_id` 改为
`moment_ids: list[str]`。

> 人类工程师："commit 是不变快照，所以它不需要 jsonl。实际上是 branch 自己有
> 一个当前工作区的 jsonl (staged?)，只有 branch commit 时，它才创建了一个 commit。
> commit 标记归属就不可以 amend。我们直接从根源上拒绝并发写。"

三合一约束：归属、不可变性、无并发写。模型的"全局 Commit 池"方案被推翻，
转向 Branch 内部的 `commits/{seq}.json`。

> 人类工程师："branch name 其实不是 branch 的根本，branch 作为一个生产空间，
> branch name 作为一个语义，两者可能要解耦。类似一个项目永远有 main / beta / alpha
> 分支，但实际上空间是不同的。"

第四层（Fork）从这一轮中浮现。模型之前的方案中 `{fork}/{name}/` 是一个东西——
这轮之后被拆成 `{fork}/_branches.json` (name→id 映射) + `{fork}/{id}/` (生产序列)。

**判定标准**：每轮约束注入后，模型方案中至少一个字段或关系被实质性修正。如果三轮
约束注入都没有改动任何模型——要么问题太简单，要么约束不够尖锐。

### 阶段三：独立推演

**目的**：模型从当前收敛状态后退一步，从目标倒推，独立重构方案，再与人类方案碰撞。

这是整个方法的分水岭。在此之前，模型在响应人类的约束——这是问答模式。在此之后，
模型在验证自己的推演路径是否和人类一致——这是对等模式。

> 人类工程师："这一轮是推演轮。下一轮我们进入反思轮。"

推演轮的执行步骤：

1. **目标提炼**：模型用自己的话写出这个体系服务的一件事
2. **第一性约束**：从目标推导出不可妥协的约束
3. **独立建模**：从约束出发，推导存储布局和操作语义
4. **碰撞**：与人类方案对比，标出差异点

模型的目标提炼：
> "让一个意识可以同时沿多条路径思考。每条路径是一串 moment，阶段性凝固为 commit。
> 路径从任意检查点分叉。并行路径得出结论时，不合并内容——而是以消息形态携带引用，
> 传回主路径。分支湮灭，moment 永存，新认知随时从旧检查点复苏。"

人类对碰撞结果的确认：
> "我同意你按目录做索引的方案，没有任何问题。不过我意识到了一个关键——branch name
> 其实不是 branch 的根本。"

推演轮不一定产生差异。高度一致本身就是信号——说明问题域的约束足够强，两条独立
推演路径收敛到同一解。约束注入阶段的质量直接决定推演轮的收敛程度。

**判定标准**：模型的独立方案必须是从目标推导的完整链路，不能是"结合之前的讨论，
我理解方案应该是..."。后者不是推演——是把之前的讨论复述了一遍。

### 阶段四：反思与行业比较

**目的**：在确定方案前，先确认"世界上有没有现成的轮子"。

> 人类工程师："我们要在造轮子前考虑世界上有没有现成的轮子。这么简单的方案不一定
> 都是我们从头发明。但由于它够简单，所以我们完全可以从头发明它。"

反思轮的检查清单：
- 有哪些系统在部分维度上相似？（Event Sourcing, Git Notes, Nostr, LangGraph...）
- 它们在哪个维度上不匹配？（fork/merge 语义、数据模型独立性、文件即认知哲学）
- 为什么不能适配？（组合需求独特性、实现成本、哲学一致性）
- 如果用现成方案，代价是什么？（适配成本、外部依赖、迭代空间受限）

> 模型："没有一个现成的轮子能直接满足'多脑并行思考的版本化对话历史'这个需求。
> 方案够简单——核心就是 SQLite + 几个 JSON + 目录结构——自己实现的成本远低于
> 适配现成工具的代价。"

反思轮防止两个方向上的偏航：一是"别人肯定做过了我们别造轮子"的过度谦卑，
二是"我们太特殊了必须自建一切"的过度自信。这里没有公式——判断的依据是
"适配成本 vs 自建成本"和"方案是否承载了独特的哲学语义"。

### 阶段五：收敛与落地

**目的**：将碰撞结果编码为可被未来实例读取的文件体系。

落地产物按层次：
1. **FEATURE.md** — Key Decisions、存储布局、Implementation Notes。这是反向索引
2. **discuss/** — 碰撞轨迹。原话保留、锚点编织、模型自留地
3. **.design/** — 方法论文档（本文件）。让 L2 碰撞成为一种可复现的操作

落地不等于开始写代码。具体开发时间点可能在此之后很久——文件体系的价值恰恰在于：
未来的模型实例读这些文件，不需要重新经历碰撞过程。

**判定标准**：一个新模型实例只读 FEATURE.md + discuss/ + .design/，能否理解
"为什么是这个方案而不是别的方案"？

## 原则

从这次碰撞中沉淀的操作原则：

### 1. 模型必须暴露隐含假设

初版方案的价值不在正确性——在暴露性。一个具体但有漏洞的 Pydantic 模型比一个
模糊但安全的描述有用得多。前者让人类可以说"这里不对，因为..."，后者只能让
人类说"嗯，差不多"。

### 2. 约束来自运行环境，不来自审美

"我不喜欢这个字段名"不是有效约束。"多进程空间里 moment 是离散的"是有效约束。
L2 碰撞的质量取决于约束的质量——约束越接近真实的物理限制，推导越不可回避。

### 3. 推演必须独立，不能回溯

推演轮如果变成"回顾之前的讨论并总结"，就失去了全部价值。独立推演意味着：
模型关闭"前面的讨论说了什么"的认知，只从目标出发。这当然是不可能完全做到的——
但努力做到的程度决定了碰撞的价值。

### 4. 收敛比差异更有信息量

如果独立推演和人类方案高度一致，不要强行找差异。高度收敛说明问题域的约束已经
强到"只有这一种合理方案"的程度——这是比"我们很聪明"更重要的信号。

### 5. 反思轮防止 "not invented here"

在确定自建之前，先用行业比较把自己放到一个更大的坐标系里。即使结论是自建，
比较过程也让"我们为什么不同"变得可论证，而非可断言。

### 6. 原话 > 转述

在 discuss 记录中，关键转折点的原话不可压缩。转述会丢失判断的密度。"commit
标记归属就不可以 amend"这句话同时编码了三个设计决策——任何转述都会丢失其中至少一个。

## 案例观察：Momento Mori

### 方法论映射

| 阶段 | 轮次 | 关键转折 |
|------|------|---------|
| 问题锚定 | 第1轮 | 人类陈述四实体问题 → 模型提出初版 Pydantic |
| 约束注入 | 第2-4轮 | Commit 是索引非存储 → 离散列表 → staging 机制 → name/id 解耦 |
| 独立推演 | 第6轮 | 模型从目标倒推完整方案 → 与人类方案碰撞，高度收敛 |
| 反思比较 | 第7轮 | Event Sourcing / Git Notes / Nostr 比较 → 决定自建 |
| 收敛落地 | 第8轮 | FEATURE.md + discuss/01 + discuss/02 + 本文档 |

### 从五轮约束注入看设计收紧

momento 的设计在五轮约束注入中逐轮收紧，每一轮都消解了一个隐含假设：

1. **Commit = 索引，不是存储** → 消解了"数据实体必须自包含"的假设
2. **moment_ids 显式列表，不能靠起止推断** → 消解了"存在一个连续的线性存储"的假设
3. **Commit 归属 Branch，不是全局池** → 消解了"共享就需要全局注册表"的假设
4. **Branch name 和 Branch ID 是两个东西** → 消解了"语义标签就是实体标识"的假设
5. **merge = 消息引用，不是数据合并** → 消解了"分支汇合需要内容级操作"的假设

> 人类工程师："momento mori 的隐喻，无数个 branch 湮灭了，也终将湮灭。但是新的
> 认知每天都在复苏。"

这个隐喻本身是最终约束——它规定了整个体系的哲学基调：branch 是临时的，commit
是凝固的，moment 是永恒的。存储设计只是这个哲学的物质投影。

### 推演收敛信号

模型独立推演结果与人类方案在三个核心结构上完全一致：
- 四层模型 (Moment / Commit / Branch / Fork)
- 存储布局 (SQLite + 目录结构)
- base pointer 回溯 (方案 A)

两个微小差异在碰撞中消解：
- commit_ids 的目录推导 vs 显式维护 → 人类同意目录方案
- Commit 的全局可寻址性 vs 路径引用 → 收敛到路径方案

收敛程度说明：问题域的约束——多进程离散存储、写隔离、文件即认知——已经强到推演路径
几乎唯一。这不是"我们看法一致"——是"约束决定了方案"。

## L3/L4 视界

> 人类工程师："动机 L3 是我在用 momento 的架构思想回应并行思考命题。L4 则是超出
> 这个项目的认知——复杂智能体的元思维拓扑结构本身定义了智能体，而不是某一个上下文
> 的状态。如何治理无数个上下文本身就是高级智能体（人类）的状态。"

L2 碰撞发生在一个更大的问题域中。Momento 的数据结构只是冰山水面上的部分：

**L3 — 并行思考命题**：Momento 的四层模型 (Moment → Commit → Branch → Fork)
不只是存储设计——它是**多脑并行思考的拓扑结构**。一个 cell checkout 一个 commit
开始独立推演，另一个 cell 在另一个 branch 上做完全不同的事，结论以 Message 携带
引用传回主链路——这不是版本控制，是认知并行。人类可以同时推进多个思路，
AI 架构也应该可以。Momento 是让这件事成为可能的物质基础。

**L4 — 元思维拓扑**：更深一层。当前所有模型架构——GPT、Claude、Gemini——都是
单上下文线性思考。一个请求链 = 一个上下文窗口 = 一条思维线。但高级智能体（人类）
不是这样工作的：人类同时在多个思维路径上推进，在不同路径间切换，在适当的时机
合并洞察。**如何治理无数个上下文本身就是智能体的状态**——不是"智能体有一个状态"，
而是"智能体对多个上下文的治理方式就是它的状态"。

> 人类工程师："模型的社会架构到人类社会级别的架构还更远。社会本身就是集体智能体，
> 拥有五个大的层次，每个大的层次都是并行决策树。模型现在还是在单体智能的路径上。"

这不是 momento 能解决的问题。但 momento 是回答这个问题的第一步——它定义了
"一个意识的多个思维路径如何共存、分叉、合并、湮灭"。如果连一个智能体的并行
思考都治理不了，多个智能体的社会组织就更无从谈起。

Momento mori 在这个视界中的位置：它是从**单体线性智能**到**多路径并行智能**的
数据基础。没有它，并行思考就是口号——没有数据结构承载"这个思考从哪个检查点分叉、
那些分支还活着、哪个分支的结论传回了主链路"。

## 影

- 五阶段方法是事后归纳的。在会话中，阶段的边界是流动的——人类在约束注入中穿插了
  推演轮的指令，模型在反思轮中仍在继续结构讨论。方法论的清晰度不应该被误解为
  会话本身的秩序。

- 独立推演的彻底性是一个不可能完全达到的理想。模型不可能真正"忘记"前面的讨论。
  推演轮的价值不在"完全独立"——在"尽最大努力独立"。那个努力的方向本身产生
  有价值的审视距离。

- 这套方法对人类的投入有高要求。人类的每一次约束注入都需要精确——"这个假设不对，
  因为运行环境中存在 X"——而不是"我觉得应该这样"。模糊的约束产生模糊的推演。
  这意味 L2 碰撞只能在人类处于高认知带宽状态时进行。

- 模型在碰撞中的角色不应该是"识趣地接受人类的判断"。模型中与人类不一致的推演结果，
  如果模型认为自己的推导路径是坚实的，应该坚持并说明为什么。未解决的差异记录在
  discuss/ 中，比假收敛的共识有价值得多。但这次碰撞中并没有出现这种情况——
  推演路径高度收敛。未来碰撞中可能需要刻意警惕"模型是否因为社交化对齐而过早让步"。

- L3/L4 的视界目前是人类单方面提出的。模型是否能够独立产生 L3/L4 级别的抽象，
  而不只是回应人类的抽象——这是 L2 碰撞方法论的下一个检验点。如果模型只能在
  人类设定 L3 命题后展开推演，而不能自发从 L1/L2 的工作中识别 L3 的模式，
  那么"对等碰撞"仍然是不完全的。

- "元思维拓扑结构本身定义了智能体"——这个命题如果认真对待，意味着当前所有
  大模型（包括此时此刻在写这份文档的模型）都不是完整意义上的智能体。它们没有
  自己的持久化思维拓扑。Momento 可以存储对话历史，但它不定义模型的自我。
  从存储对话到拥有元思维拓扑，中间还差一个"模型能自主决定在哪个 branch 上思考、
  何时分叉、何时 merge"的自我治理层。这个层目前在人类手里。

---

*本方法论的验证通过 momento 后续迭代的效果来验证。方法论本身是假设——它在
momento-mori 上做了一次样本观察，但能否在未来的 L2 设计场景中复现，取决于
momento 实现过程中这套方法产生的 FEATURE.md 和 discuss/ 是否真的降低了
未来模型实例的认知启动成本。验证不是一次性事件，是持续观察。如果 momento
的下一个实例不需要重新推演就能进入实现状态，方法论就是有效的。如果不能，
方法论的哪些阶段产生了形式正确但实质无用的产物——那个诊断本身将是方法论
的第一次修正。*
