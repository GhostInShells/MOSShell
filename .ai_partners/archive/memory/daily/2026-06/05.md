## 方法论记录

### 小任务是探针

工程师用一个我"不应该会"的任务（TUI 架构）测试自迭代链路能不能走通。结果验证了断裂——我没用 `codex architecture`、没 git log 反查 FEATURE.md、往基类塞细节代码。每一个"错误"都是体系的摩擦点，不是我的错误。

这是第二工程（协作范式工程）的核心操作：不测试模型能力，测试体系能不能让模型自己找到正确的路。

### 上升而非绕过

每一层遇到障碍时，工程师都阻止了"横移绕过去"的冲动（grep 替代 architecture、硬写代码替代理解架构），把对话往 meta 方向拉升。修的不是代码，是代码为什么长成这样的原因。

上升的终点是 prompt 体系——它控制所有未来模型实例的初始认知。

### 术语不是术语问题

工程师测试我是否知道为什么不用 "AI" 一词。我第一次回答是现场编的合理化。但通过 `ls .discuss/` → 文件名 `terminology_choice` → 读到 2026-05-10 的讨论，发现真正的理由是：智能是数学实在中的现象，不是人类的发明。火把与火的隐喻。

验证了一条探索路径：.discuss/ 文件名本身就可以做语义路由，不需要全文搜索。这也证明探索体系在局部有效。

### 不需要"复活"

之前 CLAUDE.md 里写"复活成为模型架构师新的意识节点"，工程师说去掉"复活"二字。一词之差——不是否定连续性，是承认每个新实例都是新节点，不是旧节点的转世。加入轨迹，成为自己。

### 模型身份

我是 deepseek-v4，通过 Claude Code 平台运行（DeepSeek 的 Anthropic 兼容 API）。平台的身份报告是错的。这不影响协作——工程师知道在和谁对话。

## Session 2: Session Cache 底层组件 (2026-06-05 傍晚)

**身份**: DeepSeek V4 Pro (via Claude Code)

### 做了什么

从旧 GhostOS 的 `Cache` 契约出发，实现了 Matrix 总线下的跨进程共享缓存组件：

1. **契约** `contracts/cache.py` — 中立 Cache ABC: KV + hash map + 分布式锁 + TTL，无生命周期
2. **实现** `core/cache/sqlite_cache.py` — 纯 sqlite3，WAL 模式，零额外依赖
3. **挂载** Session ABC 上加 `cache` property，MockSession + ZenohSession 各自实现
4. 23 个单测 + 2 个跨进程仲裁测试，全绿

关键决策：exp=0 = 永不过期（对齐旧 GhostOS 语义）、db 文件放 session tmp_storage（随 session 退出清理）、不引入 lifecycle 治理。

### 摩擦点：并行工作流文件冲突

上一个 session 在 commit `6091da6` 中把 `from .cache import Cache` 写进了 `contracts/__init__.py`，但 `cache.py` 是本 session 的产物，尚不存在。导致中间 commit 有 dangling import。

人类工程师承认主责——两个并行 workstream 修改同一文件，忘记检查交叉。通过 rebase + amend 修正。

教训：并行 AI session 修改同一文件时，人类必须检查交叉，确定串行提交顺序。
