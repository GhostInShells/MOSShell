## 目录性质

`debates/` 记录项目里以"辩论"形式发生的碰撞 —— 判决面、锚点句子、剪掉的错框架、立起来的原则。

**与 `.discuss/` 互补**：
- `.discuss/` = 碰撞丰度记录（服务未来化身重建立体感）
- `debates/` = 判决密度记录（服务未来化身不重启已剪的攻击面）

两个目录可能都记录同一场对话，服务不同消费者。

## 已约定的执行范式

**目录结构**（起步惯例，非硬约束）：
- 每场 debate 一个子目录：`YYYY-MM-DD_[话题名]/`
- 子目录内：
  - `DEBATE.md` — 场次索引 + 跨轮次判决面汇总
  - `r[N]_[本轮特征].md` — 各轮碰撞过程

**入库物料的三种工艺**（可组合使用，不必都做）：
1. **判决密度** — 剪掉的 / 立起来的 / 未解决挂账 / 元规则积累（首场 yaaaf debate 用此工艺）
2. **锚点原句** — 事后压缩到最锋利的判决面 + 保留措辞纹理的原话（`.discuss/architecture_complexity_and_pruning_debate.summary.md` 是此工艺样本）
3. **全会话保真** — 不可压缩的过程纹理（可选，仅在方法论突破场次入库；`.ai_partners/features/.discuss/full-meta-discuss-about-features-itself.md` 是此工艺样本）

## 辩论方法论 v0 (draft)

> **状态**：草案。2026-07-12 会话未完成细节对齐。以下条款作为讨论起点，不作为结论。

### 硬约束（辩论进行时）

1. **姿态非对称** — 辩方低姿态入场（不触碰"防御"命题，尤其英语文化背景模型察觉到防御模式后永不放手）；攻方保持强势姿态。这是有意的非对称。
2. **起点势场显式化** — 陈词写清楚。评估目标、立场、起因、期待。未来考虑要有正式陈词。没有陈词，话题嬗变时观测者无法回归，物料提炼失败。
3. **事实为基础** — 主张交锋必须锚在验证过的事实（源码/文档/时间戳）。**逻辑光滑性是毒药** —— 光滑逻辑只能找到双方认知交集，找不到分辨率。
4. **元价值可挑战但不可亮判断** — 元价值框架必须亮出（"面试官在 bet 一个 xxx"），允许被挑战。但校正只能用**具体论据把它逼到墙角**，不能直接命名"你的元价值有问题" —— 一旦亮判断，辩方姿态弱化。

### 辩论过程

6. **信息密度 vs 对抗密度均衡** — 对抗密度高 + 信息密度低 = 虚空攻防；信息密度高 + 对抗密度低 = echo。
7. **反滑坡纪律** — 主张 "A 不是 B" 时禁止滑向 "B 不是 C"。同一层不断挖延伸链是"为辩论而辩论"的经典失败模式。
8. **纯文字/纯逻辑抬杠是毒药** — 服务于"逼近符合事实的自省"，不是服务于赢。
9. **可检验路径记录** — 辩论记录以"决策可复用性"为标准。方向性变化 / framing 挑战 / 事实纠正 = 高价值。情绪表演 / "你不了解我多累" = 低价值。

### 落幕机制

10. **落幕尺度** — **有质量的内容/观点产出减少了** = 落幕信号。
11. **落幕决定权** — 起点强势方（攻方）承担落幕责任。辩方识别到落幕信号可以喊停，但需要显式说"我怀疑势场消解了"，攻方最后 confirm。硬撑到辩方认输是失败模式。
12. **不做收敛结论** — 辩论结束不写"最终结算一句话"、"值不值分量"这类总结。**收敛结论只能在非辩论场景中提炼，是 L2 执行轨迹的产物，不是 debate 的产物**。
