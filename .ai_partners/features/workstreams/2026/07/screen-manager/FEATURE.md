# Screen Manager

> 细节写进来就是第二次手工维护，必然漂移。三类读者的入口见文末「注意力分配」。
>
> 沿革：旧设计（Decision 1–11 + S1–S3）见 [FEATURE.legacy.md](FEATURE.legacy.md)。
>
> 问题清单（单一事实源）→ [screen-todo.md](screen-todo.md)。

## Motivation

最初定位「web 合成器」（窗 = URL），跑通后只剩一处站得住的核心，其余被实战否掉。
2026-09-13 翻转成「屏幕资源空间」——自有合成器仍是脊，但资源从 URL 泛化为任何可窗口化的
东西。2026-09-19 再进一步：**这块屏不是一个后端，是一套 window 语义 + 三种实现**，
其中零依赖的 webview 实现要开箱可用。

## 默认面：模式启动即打开（2026-10-10 thirdgerb 定）

screen 不是"某块屏的后端"，而是 **screen 模式启动时自己打开的那个工作台**：浏览器里的一个 Web
分屏面，别的 node 的 surface 以 item 身份被摆进去。设计目标是**桌面** —— 不是显示器，也不是播放器。
验证阶段用 Web 技术实现，理由是**最快最便宜**；qt compositor 与 os window 两档是同一语义的另两种
躯体，换躯体不改这条定位。

推论（本文其余部分据此对齐）：

- 这个页面在被打开的那一刻就是**我的桌面**，人看到的"屏"是它的 active group。
- 池子（不在任何 group 的 item）仍然存在，只是不在屏上 —— 人不看池子，模型在池子里挑。
- 多屏不是"多开几个窗口"，而是这套语义在多个显示面上的分工（W8 未验）。
- **人看到的那一面默认只有产品本身**：雨、浪、水位标、侧栏。仪表（状态行 / 帧率 / 几何 / 活动日志）收在 `--debug` 后面，且开时挂在侧栏底部——不浮在舞台上，也不跟栏重叠。**唯一的例外是"断线"**：它不是仪表，是传导，必须常驻可见；因为水位标住在 background 层（有 item 上楼就被盖住），断线的常驻出口是侧栏顶上的点与收起态边条的红色。

## 语义模型（脊柱）

### 对象模型

| 概念 | 定名 | 语义 |
|---|---|---|
| 物料 | **item** | 一个可窗口化的东西。住在**物化池**。池子在 home 上是**可见的**（2026-10-10 改：原先写"人看不到池子"，所见即池子之后就不成立了） |
| 桶 | **group** | 有序 item 列表；**空 group 自动删除**。人看到的"屏" |
| 当前桶 | **active group** | 人可切、模型可切；改变它必须回流 |
| **焦点** | **focus** | **视图**，与 group 正交：一个 item 单独占满舞台。**池子里任何 item 都能被看**，不必属于某个组（2026-10-10 取代 per-group `fullscreen` —— 旧的那个把"呈现"绑在"布局"上：桌面上的 item 根本没法单独看，切组还会丢）。**选一个基础视图（切组 / arrange / 回桌面）= 撤销焦点**，两个视图设置器不许叠加 |
| 底层 | **background** | **空屏时可见**，Ghost 不需要争取注意力就能出现的地方 |
| 姿态层 | **veil** | 最外层遮罩 + 指向/动效。`frontend` 一词弃用 |

**不变量：一个 item 在且仅在一个 group。** 不在任何 group = 离屏（还在，只是不在屏上）。
这条不变式由后端维护 —— 模型永远不需要说"从旧桶取出"，它甚至不该知道有这个动作。

### 层栈

`background`(0) → `pool` / `desktop`(2) → `scrim`(3) → `stage`(4) → `veil`(7) → `rail`(9)。

- `pool`：home 的场（螺旋铺位），**只放画像**，不放活体；
- `stage`：分格区，唯一接收指针的物料层；
- **`scrim` 必须在 stage 之下**：stage 自己是堆叠上下文，它内部元素的 z-index 出不去 ——
  遮罩一旦在它上面，整屏的页面就被压住，点不到、还被压暗（2026-10-10 真踩过一次）。

z 序只描述层，**不描述物料**：物料之间的先后只体现为分格序位。

人机交互面（输入 / 通知 / 历史）不再属于 screen —— 由 `ghost-in-web`（浏览器扩展）承担。
**归属待定（2026-10-10）**：人"切哪一组"与顶部导航栏究竟住在屏幕页里、还是住在扩展里，
这两句现在对不上 —— 待裁决，见 screen-todo O4。

### 布局：两个家族 × 一个方向参数

| 家族 | 语义 | n 的范围 |
|---|---|---|
| **grid** | 等分（`cols = ceil(sqrt(n))`，末行不满则均分整行） | 1–n |
| **stack** | 一主 n 从（主格 2/3，其余在条带里等分） | 2–n |

`dir="lr" | "tb"` 决定 grid 的换行轴、stack 的条带方位。**形状 = f(n) 的派生量，
不是模型的参数**；模型只给有序 id 列表（`arrange(ids)`）。

**序位映射**：grid 第 k 个 → 第 k 格；stack 第 1 个 → 主格，第 k 个 → 条带第 k-1 位。

**感知前提（修正 KD7 的隐含假设）**：面积不承载**连续的** priority，但承载**角色**。
「第 2 比第 3 重要一点」用面积微差表达 = 偏置通道，禁止；「这个是主角」= 名义-序位混合
通道，允许。

**尺寸不进模型上下文**（2026-10-10 判据）：舞台的像素几何（视口宽高、栏宽、格距）不搬进
模型侧的 notice / context —— 模型只给**有序 id 列表**，形状由 n 派生。屏幕页确实把几何自查
上报（stdout 的 `[client]` 行），但那是**调试面**，不是感知面。理由：模型是按个数决策的，像素
只影响渲染；把一个"视口一变就变"的数字放进上下文，是花 token 买一个它并不需要的决策输入。
栏的展开 / 收起是例外且必要 —— 它改变的是**可用区这一约束本身**，而不是它的像素度量值。

### 感知两级

| 级 | 载体 | 内容 |
|---|---|---|
| 温 | **named notices** | 状态。框架按 fragment 做 delta，只重发变化的那一个 |
| 回执 | command 返回值 | **只装 notice 载不住的**：拒绝 / 失败 / 截断 / 自动副作用 |

**notice 是状态的唯一权威来源**，回执不复述状态 —— notice 已经是 delta，回执复述就是
双重 delta。

### 主权：人管"看哪"与"node 生死"，模型管"怎么排"

| | 权限 |
|---|---|
| **人** | 切分组 + **点焦点**（选择观看对象）+ 关闭 / 禁止 node（定 node 生死） |
| **模型** | 物化、上屏、分格、排序、下 focus、navigate（自建 item 的 url） |

**视图与布局是两个命名空间**（2026-10-10）：人只改"看哪个"，永远不动"谁和谁一组、怎么排"；
模型反过来。人的视图动作**是视图事件，不是布局事件**。

### 窗口 chrome 的归属（2026-10-20 裁决）

**chrome 归屏，node 只交两样**：它那块画布，和它声明里的 label。node 不再在自己的页面里写名字。

| | 归属 |
|---|---|
| 每个窗口的标题栏 | **屏画**。左端 = node 声明里的 label；右端 = 这一块自己的动作（maximize / restore，走已有的 `focus`，不造第二套"最大化"语义） |
| 切组（换地方） | **仍在侧栏**。标题栏只放"这一块"的动作，不放"看哪一组" |
| notify 抽屉 | 屏（未落地，见 `screen-attentional-programming`） |

判据三条：

1. 三个 node 各写各的 chrome，会长出三种高度、三种按钮位置 —— 而标题栏正是最容易被各写一遍的地方；
2. node 不该知道自己被摆在哪块屏上、顶上有没有栏；
3. 标题栏是 **notify 的可见形态**：一块砖先得有名字、有它自己的那个动作，人和我才说得上"那块东西"。

**被否掉的那一版**（记下来省一次重犯）：先做成了"一条全局顶栏 + 浏览器全屏按钮"。它回答的是
"这个窗口怎么占满屏"，不是"这块砖怎么放大"——两个问题被混成一个。全局顶栏已整个撤掉。

实现：`nodes/screens/screen_manager/index.html`（`0cde24bb`）· `nodes/os/file_editor/index.html`（`257de158`）。
问题清单登记 → `screen-todo.md` W16 / O4。

### 一块屏：当前屏与遮罩（2026-10-12 定）

同一个 url 可以开在很多标签里，而每个标签的**窗口尺寸不同**。几块屏同时画，代价不是
算力，是**指向失效**：模型在"这块"上画的手势落在人没在看的那一块。所以：

- **只有一个"当前屏"**。页面自报身份（uid，存 `sessionStorage`：刷新不变、换标签变），
  节点指派一块为当前；**只有当前屏收到下行帧**（其它页收到的是"你不是屏"）。
- **人决定哪一块算屏**，方式是遮罩上那颗按钮（`claim`）。节点启动时自己开的那扇窗带
  `?claim=1`，进来就认领 —— 重启后不需要任何人再点一次；旧标签不带认领意图，留在遮罩里。
- **遮罩页面的上行一律拒绝**（回一句遮罩，页面保持遮罩）。不是静默丢弃，是"这条不归你"。
- **当前屏消失（关窗 / 断线）不自动提级**：其余页停在遮罩上等人点。自动提级等于替人决定
  "你现在看的是这一块"，而这件事正好是模型不该替人做的。

**它进感知的形式是一段画幅**：`<viewport>1815x1352@1</viewport>`。只有当前屏在上报，
所以这个数一变，就是**人换了屏**；它同时是画手势要用的尺寸。一个 fragment 两个用途，
低频、按变化报 —— 不为此另加一列窗口清单（哪些标签开着、各有几个，不改变模型下一步做什么）。

### 前景：指的那一层（2026-10-12 定）

前景（veil）不是画布，是**指**：它只回答"哪里 / 哪个"，不承载内容 —— 内容归各 item
自己的页面。所以它缺的不是更多画法，而是一套**地址**加几个**动作**。

**参考物是截图工具**（飞书 / 微信那类），thirdgerb 点的最小集：箭头、方框、圆框，各带颜色。
照搬的只有形状，**坐标系换成了地址**：我没有鼠标，而且屏幕会被重排 —— 坐标画完就过期，
名字不会。所以：

| 形状 | 说什么 |
|---|---|
| `mark(item, region)` | 填充高亮 —— 看这里 |
| `box(item, region)` | 方框 —— 就是这个东西 / 这块区域 |
| `circle(item, region)` | 圆框 —— 圈住的这个细节 |
| `arrow(src, dst, src_region, dst_region)` | 两端都是地址，指完重排仍指向对的东西 |
| `text(content)` | 大字压在整屏上（"指着说"之外的那种话） |

`region` 目前五档：full / left / right / top / bottom。更细的地址（某一行、某一帧、某个
DOM 元素）留到协议层有地址概念时再说 —— 这五档够指向一块窗口里的哪半边。

**时间：画是并行的动作，收也是一个动作。** 这条是 thirdgerb 在直播里给的，也是今天
唯一一处真正的机制发现：

- 手势**不占频道**（`blocking=False`）：几个可以同时画、谁也不等谁；`veil()` 读回和
  `arrange` 也不会排在它们后面。
- 代价：不占频道的命令**不会被 scope 取消**（实测：话说完，框还挂在屏上，读回三条
  都是 hold；反过来若占频道，两个手势就不能并行）。所以"和句子的生死同步"不能指望 scope 自动收。
- 于是把**收**做成一个带时长的动作：`clear_veil(duration)` 到点自己收，被取消时
  `finally` 里也收。**收尾要单独占一个时间片** —— 把 `clear_veil` 放在说完话之后的
  新 scope 里；排在同一个 scope 中句子后面的那种，会在 scope 收尾时被一起取消，根本跑不到。

`duration = 0` 是常驻（hold），由 `clear_veil` 收 —— 手势不占频道，所以常驻不会冻住屏幕。

**读得回来**：`veil()` 报当前画着什么、指哪儿、还剩多久。画出去的东西必须是**状态**，
不是我记得住的东西 —— 否则两秒后我就不知道屏上还剩什么。

**五档不够时：比例矩形（2026-10-12 下午，直播中补）**。`region` 也能写 `"x,y,w,h"` ——
相对这块砖的比例。起因是要圈 terminal 头部那条状态栏，五档里没有"一条"这个东西。

- 用**比例**而不是像素：砖会重排、窗口会缩放，像素矩形的正确性只在画下的那一瞬成立；
  比例跟着砖走（"坐标会过期，名字不会"的同一句话）。
- 数字**量出来**，不是我猜的：能读到那个页面的 DOM 时按 DOM 量（像素级），读不到时从
  截图里读（±几像素，够"这一条"不够"这个字"）。
- 已知的过期条件：**比例是当时那份布局的比例**。同一个 item 在窄砖里会折行、在整宽里不折，
  同一个数就会指偏。这条不接受"自动解决"，先记着 —— 更稳的锚点（节点自报区域名）判定为
  **过重**，thirdgerb 明确不要，眼下的效果够用。
- 一个测量事实要记住：**像素看得见，DOM 读不到**。屏幕节点自己既不渲染也截不了图（截图靠
  co_browser 或 push）；跨源 iframe 的像素能截到，`querySelector` 进不去。

### 墨与笔：一层，两种生命（2026-10-12 直播中定）

前景上会动的东西**不再做成积木式的动画库**（试过雨/雪/火花/扫描线，被 thirdgerb 判掉）。
这一层要动，就由模型**直接下代码** —— 和 co_browser 里开页面、artifacts 里画布是同一件事。
于是这一层只剩两种块，区别只有一句：**画出来的东西依赖地址，还是依赖时间。**

| | **墨** — `mark / box / circle / arrow / text` | **笔** — `paint(script)` |
|---|---|---|
| 由什么决定 | 地址（item + 区域），每帧重算几何 | 时间 `t`（脚本每帧被调一次，拿 `ctx, box, t, dpr`） |
| 它说的是 | 指：就是这里 | 说：看它怎么动 |
| 读得回吗 | `veil()` 报 `box #2.left`、还剩几秒 | 只能报"有一段脚本"，内容要截图 |
| 生命周期 | **同一个**：duration / `clear_veil` / 绑 scope | 同左 |

**什么时候必须用墨**：① 指一个会重排的东西（地址每帧重算，笔得自己再实现一遍）；
② 需要能被读回（我要知道屏上还剩什么）；③ 短（一句话的事不该写十行 JS）。
**什么时候非笔不可**：任何"动"的、任何"组合"的（框 + 线 + 括号 + 跑动的点 = 一棵树，
用墨要发一打命令，用笔是一段）。

**为什么坚持一层**：清场只有一个命令，谁压谁由创建顺序定；分两层就要多回答"谁在上面"
"清一层还是清两层"—— 这类"同一件事两个权威"今天已经吃过一次苦（别名那笔账）。
默认写进模型侧的习惯：**默认为墨，要动才下笔。**

**两个已经兑现的约定**：脚本抛异常时把错误画在那块砖上（"什么都没出现"和"脚本坏了"不能
长得一样）；`paint` 读回只能报到脚本第一行 —— 这是选手绘要付的代价，认。

**一条边界**：脚本拿得到 `window`（它就是一个页面函数），所以它是模型自己写的代码、
**不是沙箱**。将来要跑别人的脚本，得单独做隔离，现在没有，也不假装有。

### 时间感

命令不是单纯状态变更，有**三档时长**。第二档是跨轨道共同时钟 —— 手势与语音用同一把尺，
模型才能说出"这里（1.5 秒）是入口"并且真的对齐。

| 档 | resolve 时机 | 例子 |
|---|---|---|
| 瞬时 | 立即（回执） | `open` / `arrange` |
| 有时长 | **声明的时长结束**（不是动画真实结束） | `veil.mark(item, region, duration=3)` |
| 持续 | 直到取消（返回句柄） | 常驻高亮环 |

### 一条尺（贯穿两个方向）

> 变化后，模型不知道就会做错决定 → **说出去**。
> 模型侧进 notice；人类侧回流信号；不改变模型状态的不回流。

### 呈现模型：池子、焦点、来源（2026-10-10 定）

**一个舞台，两把轴。**

| 轴 | 归谁 | 载体 |
|---|---|---|
| **布局轴** | 模型 | 组（谁和谁一起、怎么排） |
| **物料轴** | 人 | 池子（现在开着的一切，含已入组） |

两轴都不是"地方"，是**对同一批 item 的看法**：元素只有一个家（`#stage` 的子节点，
一个 item 一个 slot，创建一次），变的只是它身上的样式（`display:none` / 网格位 /
`position:fixed`）。**把"池子"理解成拥有元素的容器，就是 reparent** —— 而 reparent 会让
iframe 重载、页面状态全丢（WD1）。

**池子的铺位：向日葵螺旋。** `r = r_max·√((k+0.6)/(n+0.6))`，`θ = k·137.5°` ——
不重叠、有机、增删不必重排全场。远近不是另设的参数，是**从半径算出来的**（缩放 / 模糊 /
压暗 / 上抬）。数量上去时螺旋自己变密，不需要手写"第几个进中景"。

**运动来自场，不来自每块瓷砖。**

- 场：缓慢自转 + 按深度分档漂移（近的动得多 = 视差）；
- **自转只在"没人"的时候走**，且**缓动到停**（指针进舞台即停）。判据：**指针不许改变靶子
  的位置** —— 一个在瞄准线下持续移动的场，是点不准的场；
- hover = **原地**放大变清（`transform-origin: center`，**不平移**）。平移会让光标掉出自己
  的边界，enter / leave 互相打架、画面抽搐。邻居只降亮度，不让位。

**池子里是画像，不是活体。** 深度里放 N 个 iframe = N 个应用同时跑。**一个 item 永远只有
一个 iframe**，只换样式 —— 与 WD1 同一条。

**焦点是一个视图动作。** 人的点击 = 视图事件，不动布局；多个入口（池子瓷砖 / 侧栏 / 退出）
必须是**同一条代码路径**，否则三条路会各自漂移（`_tap` 那次就是先例）。

**来源属于状态。** `view_by ∈ {human, model, ""}` 进 state 帧与 notice，**不靠信号送**。
理由见下表。

**可感知的四种形式（选型判据）**

| 形式 | 什么时候用它 |
|---|---|
| **named notice fragment**（状态） | **默认**。事实是"状态变了"就用它：不抢注意力、只在变化时随 delta 出现、**忙也不会丢** |
| **signal / notify** | 只给**必须驱动下一轮思考**的事（审批结果、到点提醒）——事件决定要不要开一轮 |
| **读接口**（命令） | 主动要查的时候（对账、调试） |
| **stdout** | 细节（几何、时序），平时不看 |

`aside` 是**旁路**：不打断、有空才并进来、**忙的时候会丢，且不报错**。它只配"拍肩膀"
（例如桌面圆盘的一次点击 —— 那是唯一不改变任何状态的人的动作）。**不能承载"人做了什么"
这类事实**：2026-10-10 为此白查了一轮，最后是"改成状态 + notice 片段"一次到位。

**池子里的脸（face）：待做。** `face: {line?: str ≤24, art?: url}`，节点自报。
无 face = 标题 + `icon`；有 line = 那行字当脸；有 art = 图铺满（**先只允许静图** ——
动图会把静态墙面变成 N 个解码器 + N 个注意力争夺者，而那正是我们要砍的东西）。
**摘要优于截图**：缩略图里的字在瓷砖尺寸下读不出来，一句话能读。

**已记的一笔债（渲染器耦合）**：surface 的 instruction 里"只有被 arrange 进组的窗口才点得到"
是 **webview 渲染器的实现细节漏进了契约**，换渲染器即失效。契约该说的是指针：
**舞台上当前需要人操作的那一块必须拿到指针** —— 与它归谁无关。

## 局域网接入（2026-10-24 命题，未开工）

命题：让手机 / 平板 / 电视等局域网设备也能看这块屏，并把屏上所有 webview 一起带出去；
路由由 ghost 动态管，准入默认拒绝，所有访问先登录。完整论证、行业参照与威胁模型见
[discuss/2026-10-24_lan_access_and_gateway.md](discuss/2026-10-24_lan_access_and_gateway.md)。

### 结论（已定）

- **网关是 screen 的可拆模块，不是内联代码。** `--lan` 时由 screen 组合启动，只依赖
  「路由表 + 认证器 + 占位页」三个接口，将来可原样拆成独立节点。screen 已经是所有
  webview 的聚合者，路由表天然等于它已 adopt 的集合；但安全边界要能独立评审、独立存活。
- **上游永远 127.0.0.1，网关是唯一对外 listener。** app 节点不知道 LAN 的存在；绑定地址
  与宣告地址分离。本地访问也走同一道认证 —— loopback 不是安全边界（同机用户 / 本地进程 /
  rebinding）。
- **按 hostname（子域）或独立端口路由，路径前缀被否。** 页面传输是根路径
  （`file_editor/index.html:2510` 的 `/ws`、`:1258` 的 `/renderers`），前缀必然撞墙；
  更根本的是路径前缀会把不同节点塞进同一 origin，抹掉同源隔离。
- **URL 治理只动服务端三处。** 页面本身已是 origin 相对；写死地址只在
  `WebViewDeclaration(url=surface.url)`、channel 的 `out["url"]`、`add_local()` 的绝对地址。
  不变量：**组件只知道自己在哪监听，永远不猜自己将从哪被访问**；发给浏览器的引用一律
  origin 相对，必须绝对时由网关按 `X-Forwarded-Host` 翻译。
- **路由主键是服务 address，slug 由 title 派生并持久化**（端口是运行态，名字不能随重启变）。
- **策略三层且 deny 优先**：内置默认（default deny、`terminal` 常驻 deny）→ 持久化策略
  （workspace 下 0600 文件）→ 会话覆盖（ghost channel）。放行是安全事件，必须在屏上可见、
  留审计。
- **ghost 只能自动降级，提权要本地人类确认。** ghost 上下文会被 webview 内容 / 网页 /
  终端输出污染，允许它自由放行 `terminal` 等于给 prompt injection 一条直达远程 shell 的路。
- **未准入的 route 由网关返回静态占位页，且不建立到上游的连接。** screen 保留该 item，
  `face_line` 标"局域网未授权"，不静默消失。
- **认证覆盖所有模式**：设备凭证（本地注册后发长期 token，可逐台吊销）+ 可选密码
  （Argon2id 哈希，绝不加密）。本地信任锚是**文件系统权限**，不是 loopback；注册 / 重置是
  本地 CLI/TUI，不依赖 screen 进程存活；远程设备用一次性配对码换设备 token。
- **TLS 与 Host/Origin 白名单是硬要求**：WPA2 是共享密钥，LAN 不等于可信；Host 校验是
  rebinding 防御，登录页与占位页加 `X-Frame-Options: DENY`。

### 未决

- 子域模式 vs 端口模式的默认选择；DNS 泛解析 / mDNS 的可用性。
- TLS 供给：Caddy internal CA / mkcert / Tailscale；WebAuthn 只在域名 + TLS 下可用。
- 多屏 slug 冲突；远程 Matrix cell 的 `url=127.0.0.1` 不可达（现有协议边界，本命题不解）。
- LAN 观众是"只看"还是"可操作"：屏幕可点击并回流信号，鉴权之外可能需要只读档位。

## 三层实现（可插拔）

| 层 | 实现 | 状态 | 归属 |
|---|---|---|---|

| qt compositor | QML 场景图合成器 | 设计定稿、实现待开工，见 [qt_compositor.md](qt_compositor.md) | 本 feature |

三种躯体。命名里不放任何实现名 —— 那是 `desktop-gui` 当年的死法。
