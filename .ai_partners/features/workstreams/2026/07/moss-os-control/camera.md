# Camera

> os-control 的子文档。能力落在 `nodes/visions/camera/`。
> （归域由 thirdgerb 定 2026-10-10：cameras 属于 OS control 的一份子。）

## 定位

- 它是**生产者**，不是感知节点：自己持有设备、跑采集循环、服务一路 MJPEG；
  感知由 stream node 消费那个地址完成（`NODE.md` 里写的就是这条）。
- 它**没有 channel**，但**会宣布一个 webview**——查看页就是"我能看见的东西"，
  屏幕会自动认领成一张窗口。2026-10-10 落地（`7543a751`）。
- 当天还给它长了**脸**：一行字（`live · 640×480`）加一张图（它自己那路流）。
  这张脸后来被证明是它唯一的"门"：池子里的瓷砖就是人要找它时看的地方。

## 待做：启动分两段（2026-10-10 定案，未实现）

**规矩**：节点起来之后**分两段**——**第一段只做确认，第二段才提供能力**。

```
第一段：页面服务先起，渲染"要打开摄像头吗？"；脸写 "在等你确认"
        —— 此刻**设备没开**。webview 声明指的就是这张问询页，
           所以"声明的地址从第一秒就是真的"，没有"承诺未兑现"的窗口期。
第二段：人 accept 之后 → 开设备 → provide_channel → 页面切成实时画面 → 脸变 live
被拒 / 超时：干净退出，不留半截能力
```

- `provide_channel`、设备、以及"正式内容"**全部属于第二段**。所以闸不是一个补丁，
  而是**节点的启动被切成两个阶段**，确认是第一阶段全部的内容。
- **它不是安全边界**（`warrant.py` 自己写着 declared, not enforced）。真正的授权在
  **node manager 的启动闸**（warrant 的位置），管"能力能不能被创建"；这一条管
  "这一次要不要露出来"。两者不冲突、也不重叠。
- **范式的家**：`moss skills/node-development/{node-defined-interaction, node-startup-permission}`
  （随包；样式/物料留 `nodes/` 本地）。**故意推迟**——写它要用更好的工具，而且要配一条
  **可拷贝片段**（语义共享，代码拷贝）。
- **第一个实例就是这个节点**：它的查看页本来就是 web，把那段 HTML 换成"问 + 确认"即可。

**为什么这么定、以及被否掉的三个方案**（把确认焊进 webview 协议 / 屏幕侧做行为授权 /
warrant 接进节点）在 `.moss/ghosts/moss/journal/Y2026/M10/D10/daily.md` 第十二节，
以及锚点 **1-120**（带物证文件）。
