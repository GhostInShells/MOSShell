# Discuss Node

> 来源：D20 下午的现场讨论。前半场在做 svg works，做完之后他提出"我们也需要治理讨论上下文"。

## Motivation

真实的问题不是"记不住内容"。是**分叉的行为本身没有留下痕迹**。

他一句话里可以抛出两三个方向，其中大部分当场没被讨论、之后也不再提。人于是把这些未决的方向全部扛在脑子里——不是因为他想记，是因为没人替他记。这不只是累，是**每次岔开都要付出一次注意力的迁移成本**。

所以这个节点记的不是"讨论摘要"，是三个极小的事实：

- `fork`——一个方向从这里离开主线，一句话；
- `note`——这条线上发生了什么值得留一句的事；
- `state`——它落地了、被否了、还是还开着。

其余（哪条线、走了多远、回没回来）都是推出来的。

## Key Decisions

### D1 — 节点记录的是索引，不是内容

一句话 + 时间戳，足以让未来的我从对话原文里把细节找回来。**细节留在对话里，节点只负责让它可寻址。**

他明确否掉了"每个 checkpoint 都精确记录"，也否掉了我把 checkpoint 绑到 memento commit 上的提议——commit 是段落粒度，而一句话里可能岔出三条从未被讨论的线。

### D2 — 状态是推出来的，不是字段

一条线的状态 = 关于它最后说的那句话。不需要维护状态机，也不会出现"状态字段和记录打架"。

### D3 — 人类不操作这个面

他只做两件事：看，以及点开某个点读那一句话。所有记录动作都是模型做的——因为需要被解放的正是他，如果记录要他动手，这个机制从一开始就不成立。

### D4 — 滞后提醒，不是每轮提醒

给我的那一行常驻在 notice 里：`open 3 (b1,b4) · landed 2 · dropped 1`。它**只在真的变了才变**，因为 facade 是 delta 发的，不变的 notice 不占上下文。

真正该提醒的不是"有几条线开着"，而是**这张图已经跟不上对话了**：超过阈值没有新记录时，notice 里多一句 `stale 18m`。

判据：**提醒的依据不是我记不记得（不可测），是图跟不跟得上（可测）**——时间戳的差就是证据。而"每轮弹一句记得记录"是噪声，三次之后就成了背景音。

### D5 — 呈现：心电图式的时间线

对话在持续，`now` 一直在动，所以图会一直长。做法不是缩放，是**自动延展 + 可拖拽**：

- 窗口取"最近 30 分钟"或"最近 N 条"，谁先到算谁；
- 有新记录时自动跟到最新；
- **人往回拖就停止跟随**，不然它老把人拽回去（和我说话一样：他要看别处时我不该拽他）。

分叉点画在主线上，然后垂到自己的泳道；`landed` 在末端弯回主线；`dropped` 断在半空带一个叉；`open` 虚线伸到"现在"。

### D6 — 导出与 svg works 同形

`.jsonl` 是记录本身（可加载回来），`.md` 是纪要（**从记录生成，不手写**——手写的摘要会变成第二份真相）。

### D7 — 空白板就是 `untitled`，从那里开始建

节点起来时如果什么都没接上，板上是一个没有主题、没有分支的空会期——不是错误，也不是"请先设置主题"。每次讨论都从零开始建，主题可以后起，也可以一直不起。他确认：这个入口是对的。

## Exploration paths

- 否决：把 checkpoint 绑到 memento commit 坐标。段落粒度，撑不起"一句话三个分支"。
- 否决：把讨论状态塞进 features。那会让工作流的状态语义往对话层漏。
- mock 阶段做错又改回来的一条：分叉点一开始画在泳道上，应该在主线上。

## 未决

- `note` 会不会被用得太多（每条线都补一句 → 图变噪声）。观察一段时间再说。
- 一条线"重新打开"要不要单独记：现在 `state(id, open)` 就够了，但历史里看不出"它曾经被关掉又打开"。
- 接进 `deepseek`/`moss` 的启动流程——节点开着但它得被人记起来才会被用。

## Implementation

`nodes/webview_apps/discuss/`（单例）：`topic` / `fork` / `note` / `state` / `list` / `export` / `load`。

页面是一条时间线：主线 + 泳道，点开任意一点读那一句，拖拽看历史，新记录自动跟。
