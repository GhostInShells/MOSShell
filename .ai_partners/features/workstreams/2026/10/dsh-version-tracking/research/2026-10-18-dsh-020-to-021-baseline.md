## 2. 鉴权事实（决定 launcher 契约）

来源：`packages/client/connection/src/browser-auth.ts`、
`packages/client/connection/README.zh.md`、`packages/bundle/web-app/README.zh.md`。

| 事实 | 位置 / 含义 |
|---|---|
| 启动 token 每进程**内存生成**（`PROCESS_LAUNCH_TOKENS` WeakMap），**不落盘** | `browser-auth.ts:63` `processLaunchToken` |
| 打印带 token 的 URL 是 `dsh-web-app` 的职责；`DSH_WEB_URL` 给 agent 的是**无 token** 版 | `web-app/README.zh.md:109` |
| token 交换只接受 `GET /`（根路径）；HTTP 载体不接受 `Authorization` header token | `connection/README.zh.md:41` |
| 落盘的是 **cookie 签名密钥**（`$DSH_HOME/.credentials.yaml` 的 browser-session grant） | cookie 默认 30 天，绑 host+port+scheme，HttpOnly / SameSite=Strict |
| API cookie 由 `/connect` 签发，peer 由**一条生命周期 socket** 持有；socket 关闭后该 cookie 的 HTTP 与重连**被拒** | 不构成长期凭据 |
| `/connect` 与 `/api` 桥都由 `client-connection` 注册到 `webServer` | `client-connection/src/index.ts:141–163` |

推论（供 launcher 契约使用）：**token 是 bootstrap，cookie 是资产**；稳定鉴权 =
一次性 token 换 cookie 后持久化复用，token 只在首启 / 换 home / 换端口时出现。

## 3. 组合事实（决定"去 web"的成本）

来源：`packages/bundle/*/cordis.patch.yml`。

| bundle | 条目数（0.2.0-rc.2 → 0.2.1-rc.2） | 其中 `client-*` |
|---|---|---|
| `base` | 94 → 96 | 0 |
| `web-app` | 85 → 90 | **59** |
| `headless` | 2 | 0 |
| `sdk-app` / `acp-app` | 4 / 2 | 0 |

- `typert` / `api-gateway` / `remote-access` 都在 **`base`**；`host-webserver` 与
  `client-connection` 在 **`web-app`**。
- `packages/client/` 包数 68 → 71（新增 `ui-plugin-market`、`ui-secret-mask`、
  `ui-deepseek-model-label-1017`）。
- 组件增量：`apps/web/` + `packages/client/` = **1375 files, +50859 / −8879**；
  `packages/experimental/` = 816 files, +70012 / −3306。
- 顶层包重组：`hooks` / `runtime-diagnostics` / `webhook` 从顶层移入 `packages/experimental/`。

**gateway-only 组合的四条（实验性，未实跑）**：
`base` + `client-connection` + `host-webserver` + `api-remotes`（+ 自有插件）。
可得全量 Remote 面、`$events`、插件 `ctx.webServer` 路由；不含 59 个 `client-*` 与
`frontend-static`。缺口：该组合没有打印 token 的 startup。

## 4. 非 web 驱动面（决定"降级"是否可行）

- `dsh --profile sdk`：stdio JSON-RPC，插件 `@deepseek-ai/dsh-sdk-jsonrpc-server`；
  0.2.0 → 0.2.1 协议动词从 `session/prompt` 增至
  `session/prompt|resume|wait`、`session/working-directory/get|set`。
- `dsh --profile acp`：Agent Client Protocol，独立的权限提示面。
- **两者都不经过 gateway**：`git grep apiGateway|remoteAccess|typert-gateway` 在
  `packages/sdk/` 与 `packages/acp/` 下为空 —— 它们是平行的第二、第三套驾驶协议，
  不是 gateway 的另一种传输。
- 进程内驱动入口存在：
  `ctx.connection.createPeer({ principal: { kind: 'owner' }, interactions: 'answer' })`
  （`client/connection/src/rpc-host.ts:140`），不需要 HTTP 鉴权。
- home 级 patch 是启动链路的一层（叠在 profile patch 之上，HMR 监听），
  因此"注入与具体 profile 无关"在机制上成立。

## 5. 版本宣告（决定"兼容各种启动方式"需要什么）

- gateway 的 wire 上**没有版本**：`RemoteHostFacts` 只有 `home` 与 `isLoopback`
  （`packages/api/gateway/src/client/index.ts:120`）。
- `serverInfo` 只出现在 SDK / MCP 侧；dsh-fusion 已记录其值恒 `0.0.1`。

推论：外部驱动必须自带版本探测（spawn 时读 `dsh --version` / 安装树 `package.json`；
attach 时由配置显式声明；再以能力探测兜底），不能依赖协议自述。
