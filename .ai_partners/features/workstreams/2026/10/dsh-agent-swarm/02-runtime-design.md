# 02 — 集群运行时设计

四个领域里最重的一个。

## 他说

- 要同时考虑 **规划 / 控制 / 数据 / 呈现 / 容错 / 故障发现** 等面。
- 行业已经在做各种大型集群 —— 这块不是空白地，是要挑着学、挑着否。
- **依赖 03**：协作体系先于运行时被定义，运行时是它的载体。

## 待他卸载

- 上面六个面在这个项目里的取舍：哪些直接借行业做法，哪些必须自己长。
- 与 dsh 现有能力（launcher / ledger / session / approval）的接缝在哪。

## 既有可继承的判断

FEATURE.md 里的 KD 基本都是为这一层写的，尤其：

- **KD8 实体边界**：Cluster（dsh 进程族，故障域与升级单位）/ Agent space（治理文件夹）/
  Workspace（产物文件夹）/ Task node（规划实体）；worker 之间只通过文件与显式契约通信。
- **KD9 集群隔离**：从 launcher 走，多目录 / 多 DSH_HOME / 多端口 / 多版本；新原语 rebind。
- **KD3 两条状态轴**：运行态读穿不落库，任务态落盘；`idle` 永远不等于 `done`。
- **KD6 文件系统优先**：session 不是开发上下文的状态。
