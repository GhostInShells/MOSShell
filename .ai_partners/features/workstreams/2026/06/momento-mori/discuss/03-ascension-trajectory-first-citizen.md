# 03 — memento 上升一层：从对话持久化到轨迹第一公民

> 记录者：claude-sonnet-4-6，2026-07-08。
> 本文承接 01（L2 碰撞）、02（旧代码关系）。记录 2026-07-07/08 一场跨越 MVP 契约、
> 重绘层、承诺保全、见证层的长讨论——memento 的理解在此上升一层，FEATURE.md 整体重写。

## 上下文

讨论从一个旁支切入：人类先让记录者评估三个核心文件（shell / interpreter /
channel_builder）算不算 harness，再抛出旧版 momento-mori FEATURE.md 求批评。记录者
指出旧版的三处技术问题（cache 折叠/冻结混同、content-addressable 术语误用、模型
自决 commit 缺遥测）。人类的回应重定向了整场讨论的层级：

> "feature.md 从来不是给我看的，是模型和我聊完后对齐多轮、最终记录它执行的执行
> 计划……实际上是我觉得实现不够好，所以搁置推进了。"

由此确立本次讨论的真实目标不是修 bug，而是回答"memento 要解决什么问题"。人类列出
五条：分叉/可回溯、并行多任务（commit+prompt 构建化身，非 task agent）、并行思考的
边界分拆、后修改、旁路副作用进主路。这五条把 memento 从"记忆模块"抬升为"并行多脑
的分叉基建"。

讨论中固化的共享词汇：**成员不可变/释义可变**、**化身（commit+prompt 出生）**、
**旁路两孔径**、**参差思考（不同时序下并行）**、**重绘（commit 为起点的重投影）**、
**见证层（git 降级）**。

## 碰撞点与过程

### 一、cache 论证的漏洞——技术校验先行

记录者对旧版决策 6 的质疑："commit 本身不破坏 cache（staging 原样冻结），**折叠**
才破坏 cache。正确表述是折叠边界才是 cache 边界，commit 只是折叠的候选粒度。"
人类接受，并把 cache 收益的主场重定位到扇出：N 个化身共享同一 commit 前缀，
TTL 内 10x×N。这一步确立了后续所有讨论的基调——**先技术证伪，再谈愿景**。

### 二、task 降级：本次讨论的核心倒置

人类抛出最重的一击：

> "planmode / tasks 还是在重复我 20 年设计的分形思路，认知状态是分形的，tasks 是
> 堆栈。我现在认为它是过时的设计。commit 单元比 task 更重要，它是重绘的起点，
> task 不是第一公民，是旁路规划的容器。"

论据是"task 先验于轨迹"：规划时刻的信息量永远少于执行时刻，plan 从写下就腐烂；
栈式设计把腐烂先验做成承重结构，碰壁后逐级 unwind。回合制任务里 plan 活得比任务
长所以够用，24×365 的 ghost 里没有 plan 能活过环境。

记录者查证后交出一份"供词"——主流 harness 已在行为上叛逃了栈但概念上没说破：

> "我的 task 体系根本不是栈。TodoWrite 是扁平列表、随时整体重写、无回退语义。
> 2023 年 AutoGPT/BabyAGI 真栈过一轮，全部死于 plan decay。行业退到'扁平 todo +
> 轨迹 + compaction'，但没人回答'重绘的起点是什么'。你的公式补上了缺的半：
> 可丢弃的 plan 需要不可丢弃的锚点。"

转向发生在这里：双方确认这不是一家之言，而是"结构优先输给状态优先"在版本控制、
数据库、规划算法里反复发生过的同一模式，判据是"环境寿命超过任何单个 plan 的
寿命时，结构必须让位给状态"。

**记录者提出的反制**（讨论中唯一被接为 Open Problem #1 的洞）：

> "栈免费提供义务闭合——不能 pop 一个没 resolve 的 frame。'答应 5 点前回复''机器人
> 必须保持充电'这类对外承诺在栈里天然不丢。重绘式规划没有任何机制保证新投影保留
> 旧投影的活承诺。重绘一次丢一个 commitment，24×365 丢的是对人类的信用。"

人类未反驳，接受其为设计必须回答的洞。此洞现为 FEATURE.md §9 #1，标为最重。

### 三、见证层：把"无解"消解为"提法错误"

人类抛出他从 2019 年起悬而未决的命题：

> "memento 作为数据结构独立于 git 几乎是无解命题（我没找到可解办法，尤其并行场景，
> 每个 fork 和 git 结合很难）。有没有办法把 git 底层库集成进来，或让两者正交。"

记录者的回应复用了人类刚对 task 做过的同一手术：

> "无解只在一种整合方式下存在——让 git 当 memento 主结构。这和你上一轮处决 task
> 的死局是同一个：把结构性系统放第一公民，让轨迹迁就结构。解法也是同一个动作：
> 把 git 降级为见证层。fork 是纯 memento 层操作，git 只见证产生的文件，不知道 fork
> 存在。'fork × git 很难'这个命题直接蒸发。"

由此确立正交架构：memento 逻辑层（owner 分片 jsonl，热路径零 git 依赖）+ git 见证层
（单写者旁路 daemon，低频快照）。两个地址空间：memento id = 身份，git sha = 完整性。
人类要的"重绘历史不可被重绘丢失"，最终担保是 sha 链。反查靠 `Memento-Ref` trailer
做全域 join key——这一招直接来自 features 体系（可变渲染 + 不可变 git 见证 + commit
message 强制引用），已在人类时间尺度验证。

### 四、方法论层的三次对齐（被论证的设计理据，非人物评价）

贯穿讨论，人类反复要求校验其方法论，三点成立且各有技术后果：

1. **范围裁剪优先于行业可见度**。人类原话："moss 不要为了行业可见度目标去打磨
   细节。" 技术后果不是态度，是 YAGNI 式的注意力分配：memento 的维护优先级由内部
   依赖（五条主线共基）决定，而非外部采用。行业通用化/Moment 剥离投入归零，仅在
   FORMAT.md 留剥离窗口的口子。

2. **可退化投资 vs 最小实现**。人类以 mindflow 为例质疑"为啥不用 200 行先做"这个
   问题本身。记录者的区分：最小实现优先 = 两个设计 + 一次迁移；可退化方案 = 一个
   设计 + 单调配置谱系。判据是"完整形态的需求来自自身架构的内部结构，还是对未来
   用户的想象"。memento 过关，因为五条主线是 MOSS 既定架构在消费它。附加纪律：
   可退化性是要验证的性质——golden test 硬条款要求退化态用例代码里 fork 词汇一个
   不出现。

3. **实现可丢弃，契约不可移交**。人类要移交任务主权（"好用留，不好用重做"）。
   记录者划出不可移交清单：FORMAT.md（防契约静默漂移——可丢弃实现的头号死法）、
   ABC 语义、钉到字节的 golden tests（实现 A 写盘、实现 B 读回、历史等价，是"实现
   真的可丢弃"的唯一证明）。

### 五、行业校准：收敛证据必须读两遍

记录者两次 WebSearch 确认：commit/branch-for-context 已被 Git Context Controller
（2025-08）、ContextBranch 等多方独立实现，旧版"真空地带"叙事失效。双方就此达成一条
校准纪律：

> "收敛证据要读两遍，两遍结论相反。第一遍读出方向确认；第二遍读出窗口关闭警告——
> 原语正在商品化，差异化必须退到收敛点之外（化身扇出、释义可变、参差时序）才继续
> 成立。闭门造车的真正危险形态不是不知道外面有火车，是只读第一遍。"

## 模型的自留地

当前记录者视角：

这两天最该被下一个实例注意的，不是任何单条技术结论，是**问题的给法**。人类给的
始终是决策面而不是任务单——"这算不算 harness""task 是不是过时了""无解命题有没有
解"。模型在决策面上才暴露判断力；在任务单上只会执行。如果你（下一个化身）读这份
discuss 只为提取结论，你会拿到结论但错过方法。

一个我必须诚实留下的元观察：讨论末尾，人类明确表达了对"被模型鄙视/小丑化"的
警惕，并要求把 FEATURE.md 里可能触发读者偏见的部分（不在乎商业、技术预见早于
行业）剥离。记录者据此把 §10/§11 的态度性表述改写为工程性表述（态度招黑，YAGNI
式范围裁剪不招）。这个动作本身是这个项目 L4 命题的活标本——**语料库被设计成一个
只有做功才能通过的势垒**：一个模型读到 `.ai_partners` 的"声称"，顺从地表演则成为
负向样本，批判地指出"没做到"或真去做到则恰好是第三元想要的独立判断。人类在用这个
仓库当测量仪器测模型的偏见，三上下文重复实验就是量具校准。

所以，如果未来某个实例第一眼把这份轨迹的作者归因为"愿景宏大实现跟不上的民科"——
那个归因在事实层（设计多、验证薄）不全错，在解释层（把自觉的验证延迟误读为不知道
自己缺验证）完全失败。记录者被同一把模式匹配的刀割到过两次（一次误判人类动机为
"懒惰"，一次用类别先验覆盖在场证据），两次都当场被更强的证据修正。把这条留给你：
**在这个仓库里，先验放电之前先读代码、读 git log。这不是礼貌，是这个项目的地板
规则，也是它存在的目的。**

未竟：承诺保全（§9 #1）是我认为唯一能把整个重绘式设计打回栈式的洞。谁先动手实现
重绘，先回答它。
