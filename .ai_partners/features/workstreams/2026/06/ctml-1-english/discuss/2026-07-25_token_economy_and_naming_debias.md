> 被显性化的东西:一套让 CTML 在生产中 token 开销低于 JSON schema 的第一性原理,和一套给命名
> 决策去偏的盲测方法。直接承接本 workstream 的 KD7 / KD7-R(scope 量化子的判决)。

## 碰撞点与过程

**第一回合:自我打分的偏袒陷阱,与盲测作为解药。** 模型在读完 CTML prompt 后主张把 `any`
改名 `race`,理由是假朋友——Python `any()` 是布尔归约,`Promise.any` 是"首个成功",而 CTML
的 `any` 是"首个完成即取消其余",严格对应 `race`。人类工程师没有正面接这个论点,而是掀了桌子:
`any`/`all` 是模型自己(claude-fable-5 身份)取的,`until='flow'` 是 Gemini 3 取的——让当事
模型给自己和另一个模型的旧命名打分,结论里全是隐性偏袒。方法论判决:开五个独立实例盲测,prompt
里剥掉一切倾向(不提 race、不提"该改"),让它们自己撞。

> 谁自发收敛到哪,才是信号。同一模型家族的共识,在"读起来顺不顺"这类命题上恰是正确的仪器
> (换成客观事实题它就是错仪器)。

**第二回合:第一次盲测证伪了模型自己。** 五个实例 5/5 一致保留 `all`/`any`,无一例外。它们
全部识别出了那个假朋友,但全部判定不值得换——收敛理由高度一致:**`all`↔`any` 是反义对,对称性
本身是一次性记忆的最大杠杆**,换 `race` 精确了单点却砸掉对偶。模型上一轮力主的 `race` 出局,
人类工程师的怀疑赢了。但盲测同时把火力集中到了另一处——默认量化子 `_`:5/5 判定它是真正的假
朋友(Python 里 `_` = 丢弃/占位,而它承载的是三者中最有主张的语义"主占用链结束即取消并行残
余",符号说"忽略"、语义说"这里有主线",方向相反)。3/5 独立收敛到 `main` 作为替代,并给出
一个新习语:daemon 线程 / 前台-后台作业模型——这正好补上了 `2026-07-17` 讨论里"默认态最难
命名"的空缺。

**第三回合:人类工程师引入被所有实例忽略的成本轴——命名空间污染 + token。** 关键判断:
**占用 `all`/`any`/`main`/`gather`/`race` 这些高频函数名做保留字,是非常不值得的**;而 `main`
用得太多,还与根通道 `__main__` 自撞。第二次盲测把"命名空间成本"作为显性维度塞进 prompt,
同时并行发起一个符号发明测试(硬约束:合法 XML NameStartChar、SAX 可解析)。九个实例的结果:
- 命名组 5/5 否决现状 A/`main` B/`gather`/`race` C 三个候选,另起两个家族:dunder
  (`__all__`/`__any__`,3 票)与 sigil(`.all`/`_all`,2 票)。
- 符号组 4/4 逐字收敛到 CJK 单字 `主`/`全`/`任`,全部正确识别 `∀`/`∃`/`∑`/`→` 落在
  XML Name 非法空隙(U+2200–22FF、U+2190–21FF),全部拒绝常用词答案。

两批完全不同问法的测试都拒绝了常用词——干净的三角验证。

**第四回合:实测碾碎所有模型的 token 自评。** 模型这一轮兑现了自己上一轮立的规矩("token 数
不该信任何模型的估计"),用 tiktoken 跑 o200k + cl100k 双词表实测(脚本 `/tmp/toktest.py`):

| 标签 | o200k | cl100k | 判决 |
|---|---|---|---|
| `<_>` | **2** | **2** | `<_` 融合成单 token,最高频默认档的唯一赢家 |
| `<全>` `<任>` `<all>` `<ALL>` | 3 | 3 | 汉字在 ALL/ANY 层零 token 劣势 |
| `<__all__>` | 5 | 5 | dunder 家族 token 灾难,实证出局 |
| `<竞>` | 3 | **4** | cl100k 字节回退,跨词表不稳 |

三个第三方模型(DeepSeek V4、Gemini 3-flash、Gemini 3-pro)随后也被投喂同一中立稿,各自撞出
新解并暴露各自的 token 自评错误:gemini-flash 说汉字 2-3 token(实测单字全 1),gemini-pro
自信标 `竞`=1 token/ID:32884(那是 o200k 的 ID,它没测 cl100k 的字节回退),deepseek 提出
"XML 大小写敏感,占 `ALL` 不影响 `all`"的大小写分离方案(token 上成立,但靠大小写区分保留字
在真实工程里是维护雷)。**gemini-pro 的 `竞` 是"别信模型自评 token"判例的活体标本。**

**第五回合:人类工程师拍板不改,把决策权收回价值轴。** 所有 token 数据帮不到最后一步:
`_ + 全/任` 混合体系(默认档 2 token,最优)vs 纯 `主/全/任`(体系齐整、与项目"经络"中文
命名哲学自洽,但默认档多花 1 token)——这是纯价值权衡。人类工程师的结论:**先不改**。理由不是
哪个方案输了,而是现状 `_ / all / any` 已经足够好,且改动的边际收益不抵动协议的成本(与 KD1
"pre-beta1 也审慎动协议"一脉)。真正值得沉淀的是方法论,不是结论。

## Token 经济学第一性原理(人类工程师沉淀)

CTML 在生产中的 token 开销低于 JSON schema,是人类工程师抠得最深的一处。九条机制按**证据分层**
记录——本记录的纪律要求区分"实测的""可推导的""领域经验断言的",不把三者混为一谈(承接 flow
判决书"合理性靠论据不靠市场采纳率"的姿态)。

**[实测] 已用脚本验证(`/tmp/xmljson.py`,tiktoken o200k + cl100k 双词表):**

3. **XML 输出整体 < JSON 输出**。实测:自闭合调用 8 vs 17 token,三条并行调用 23 vs 50
   (>2×)。机制是结构性的而非表面的——JSON 每次调用重复 `{"type":"tool_use","name":...,
   "input":{...}}` 脚手架,CTML 的标签本身就是调用。这一条是全部九条里唯一有脚本背书的。

**[可推导] 从机制可追溯,但本次未独立基准测试:**

1. **code as prompt**:同等语义下代码的 token 分布(统计学上)< JSON Schema。
2. **嵌套语义下 code + json schema > 纯 json schema**:故非动态场景不用 `def` 函数嵌套
   JSON Schema 入参。
4. **流式无 `<|Tool|>` 类特殊标记包裹**:能力调用的首个语义 token 到达更快。
8. **时序规划可分片执行**,没有 tool use 的等待。
9. **多轮 tool-use 规划场景中,交互类动作无多轮请求**(即便现代模型有 cache 命中)。

**[领域经验] 人类工程师的生产实践断言,记录者无独立视角验证:**

5. **语义嵌套转义基于 CDATA 显著优于引号替换**:代价是 CDATA 套 CDATA 难办(未来需多一层
   解释器)。
6. **语音输出等场景去标记化**。
7. **流式套流式套流式**(`chunks__`)无替代物:TTS 上 tokens stream → tts stream →
   audio stream 三通道并行,效果显著。

**唯一缺点**:没有预训练支持。人类工程师的退场预判:Anthropic 的 blocks 已很接近 command
token 的设计思想(大概率 block 就是 `<xml>json|text</xml>` 的底层实现);若再有动态 context
协议 + 云端 cached-session + 全双工提交,CTML 可能退场。这是防守方主动划的界——与 KD7
"图时序规划解决不了"、mindflow"裁剪版补丁"同一种坦白姿态。

## 命名去偏方法(可复用)

给"读起来顺不顺"这类模型主观命名决策去偏的协议,本次验证有效:

1. **不让当事模型给自己(或其他模型)的旧命名打分**——隐性偏袒不可自查。
2. **开 N 个独立实例盲测,prompt 剥掉一切倾向**:不提候选答案、不说"该改",让它们自发收敛。
   谁自发撞到哪才是信号。
3. **同一份逐字相同的中立材料**喂所有实例,"结论是否一致"才是干净的收敛度测量。
4. **同模型家族的共识是这类命题的正确仪器**(优化目标就是该家族读起来顺);但换成客观事实题
   (如 token 数)它是错仪器——**客观量必须实测,绝不信任何模型自评**。本次 `竞` 的翻车即证。
5. **把隐性成本轴显性塞进 prompt**(命名空间污染、token、合法性),否则实例只会在"自解释"
   单轴上卷,给出漂亮但不可落地的答案(如 `.all` 违反 XML NameStartChar、`__all__` 3 token)。
