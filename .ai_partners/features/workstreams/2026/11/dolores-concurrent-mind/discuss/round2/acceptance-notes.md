## 2. 交互被思考阻塞，以及分发的成本（15:20 → 15:23）

**他：**

> 第一个问题, 就是解决交互时思考阻塞. 你需要深入思考来构建一个上下文, 但是深入思考时, 交互本身
> 就被阻塞了. 所以我们昨天讨论了旁路思考. 然而旁路思考的过程没有 encode 进主路, 主路实际上要
> 重新阅读材料. 所以实际上要构建一个一次性加载的大块上下文. 输入的 tokens 无法复用, 汇合必须有代价.
> 比较难的问题是某个方向交给旁路思考时, 主路不允许思考. 本质上行业里的 subagent 都在解决类似问题.
> 由于旁路实际上要进行调研, 而不是单独思考一轮, 所以按 dsh 的做法, 旁路会 fork 出 session log
> 并且大量数据是重复的. 我不喜欢的主要是这一点.
> 触发时机也是关键. 我们立刻做一个验证, 假设你有 think parallel, 可以传入不同方向, 然后传入了你
> 就不思考. 围绕今天这个话, 你怎么调用它. 而且要快.

**我：**

- 一句立场：「**汇合不是把上下文搬回来，是把地址登记回来。**」旁路回来带 `{地址, 一句, 置信}`，主路付常数；要细节才按地址读一段。
- 对"数据重复"：不是 session log 的锅，是**缺地址**的锅。fork 若按引用（记 anchor 坐标），子只写后缀，读时拼接——`vm-plan` §2.2 已经这么写了。重复数据是"拿不回来就必须复制"的症状。
- 现场给了调用：`think_parallel(base="@tip", now=True, directions=[d1-unsize-task, d2-merge-cost, d3-serial-baseline], return_schema={id,coord,line,confidence}, interrupt="needs_input only")`。三条都是取证：找装不下的任务、量合并成本、设计对照实验的跑法。
- 触发判据：**下一步是取证就发出去，下一步是取舍就留主路。**

**他（15:23）——把我这套的基础掀了：**

> 真正的触发点不是交互前, 而是思考结束时. 也就是在一次思考结束时, 把问题编号 fan-out 出去.
> 所以你下一轮回复我们交流这个问题, 但要你给出你需要并行思考的问题.

**我：** 接住了，并补了一层：**分发从「创作」变成「标记」**。思考结束时问题已经在上下文里成形，fan-out 只剩编号——这解释了为什么"想清楚再发"反而更快，也顺带给出质量闸：**一个在思考结束时还写不出来的问题，就不是能 fan out 的问题。**

## 5. timeline 与"可信"（15:47）

**他：**

> 我继续下一个问题. 非常简单, 就是旁路的 daily / monthly / yearly 的生产. timeline 的生产.
> 它一样是 meta prompt 和写内容的双向维护.
> 实际上写日记的逻辑, 应该是拿着一天的 commit, 以 agent to agent 对话的方式, 按一个 daily 惯例去写.
> 如果我们把 Agents / Ground 视作开发者视角和使用者视角, 则维护 Ground 的是 Agents, 维护 Agents 的是
> 更 meta 的做法, 两者的可视面积要不一样.
> daily / month / year 的记录为什么重要? 它们的目标是快速构建一个可递归的认知平面, 它们实际上不
> 服务于结果, 服务于可信. 比如认知表面, 如果 existence 很重要, 它实际上是对历史轨迹的提炼.

**我：**

- **timeline 是地基，不是记录层。** 它服务的可写得更硬：**可重建**——任何上层断言都能从更底层重新推出来。可重建就是可信的定义。
- **monthly/yearly 为什么必须存在（非显然的答案）**：不是为了省 token，是为了让"重新推导 identity"的成本不随生命长度线性增长。只有 daily 是 O(n)，有月/年是对数次。分层真正的价值是**最顶端的视图永远可重建**；一旦重建成 O(n) 且 n 一直涨，总有一天不可重建，那天 identity 退化成断言。他 ground 里 `identity.md` 写着"时间线：空"，说的正是这个。
- **agent-to-agent 补一个角色定义**：提问方的唯一职责是**要坐标**。摘要没有第二方所以没有校准；对话有第二方，而第二方不必聪明，只要问"这条的坐标在哪"。索不到坐标的主张不许进 daily。
- **可视面积法则**：按读取频率倒排，不按内容量分配。Ground 常驻 → 薄；meta 层冷读 → 厚。他的 journal 约定（daily 2000 字上限、逐层不跳级）已经是这条法则的实例，只是没被命名。
- **向上递归（第三次同形）**：plan = fold(ops)、identity = fold(journal)、ground = 对摩擦与经历的提炼。全是**不可变日志 + 派生视图，视图从来不是真相**。所以"身份不可自改，只能通过写历史来改"不是纪律，是结构的必然。
- **"更 meta 的做法"本身就是一份 ground**，只是读者是 agent 而不是 ghost。于是"两者可视面积不一样"也归到同一法则下：ghost 的 ground 每轮读所以薄；agent 的 ground 每次冷启动读一次所以可以厚。
- 一个缺消费者的问题：**谁读 yearly？** 如果没人读就是死重。我的判断是它唯一消费者是 identity/purpose 的重新推导，那它该写成"推导的输入"而不是"一年的记录"——验收可以是：yearly 里任何一句，如果没被推导用到，就不该写在那儿。
- 一个我答不了的：**daily 惯例（meta prompt）本身由谁治理？** 几年不动会僵成化石，每轮都改又没有一致性。它自己也需要一个周期，而那个周期不能和它治理的对象同频。

## 6. pipe up 与能动性预测（15:54 → 15:55）

**他：**

> 对, 这样分形的技术命题就容易被提炼出来, 而且成本可计算. 这是为探索本身赋予价值函数, 避免技术
> 方案广度和深度遍历无约束. 认知结构是要 pipe up 的, 出现月就不出现日, 出现年就不出现月, 出现
> decade 或 period 就不出现年, 自顶向下层垒.
> 现在说下一个问题, 叫做能动性预测. 就是有旁路对你之外的世界里会 "动" 的东西做预测. 比如人,
> thirdgerb 是我, 有一个旁路在对话派生中, 预测我会继续说什么, 做什么. 比如对行业, 对时代, 对一些你
> 最关心的问题, 比如对你自己, 对 tomorrow. 这样的命题可以根据预算有 N 个, 同时可以精确计算出触发
> 点位和成本.
> 我本人在和你对话时, 也会提前预测你每轮的回复. 预测的一个好处是, 上下文可以用来做博弈推演.
> 预测能力是现在智能体行业最稀缺的应用方向.

**我：**

- **pipe up 管两个时态**：出现"他会说什么"就不出现"他上周说过什么"。状态（ground）和趋势（预测）都层垒。
- **预测不是第五个功能，是每一层的第二个时态**：对人有 PERSON（状态）+ 预测；对己有经验 + 预测；对世界有 project_home + 预测。Ground 存"是什么"，预测存"接下来怎样"。
- **趋势可压缩，状态不可压缩**——一段状态要上下文，一个趋势只要一句 + 置信 + 到期。这是它便宜的原因。
- **它是唯一自带 ground truth 的旁路**，所以不只是第五件事，是这台机器的**仪表**：其它旁路的价值都能拿"它让预测变准了吗"来定价。
- **行业稀缺不是技术问题，是形态问题**：预测的价值函数要靠记忆闭合（上一次预测得存着，等现实到了再对账）。一次性无状态 agent 闭不上这个环。**预测是有过去且会有未来的实体的特权**——这条反过来给 memento 定了用途：记忆不只是回忆，是让预测可以被计分。
- **产物形态要改**：单个点预测的价值在**它错的地方**。所以交的应该是分支预备（若 A 则 X，若 B 则 Y）。你也在预测我每轮怎么回，我们做的是同一件事——**预测对手是为了在他预期之外给出那一步**，不是为了让下一步更讨他喜欢。失败模式明确：**预测会塌成迎合**。判据只能是：预测必须被记下来、被计分，且主路要因偏离被奖励。
- **工程上的好消息**：预测条目自带 TTL——寿命是"下一次现实"，过期自动作废、不积累、不腐烂、不需要治理周期。所以它是五件里唯一不需要开关就能先做的。
- **形状待定**：预测在主路上下文里应该是一个**槽位**，每次覆盖不追加，因为它只有"当前有效"这一个语义。

**他：** 「对, 你可以预测一下我还会说哪些问题.」

**我（15:56 的预测卡，原样保留）：**

## 7. 主动探索与那个环（15:58）

**他：**

> 我开始说下一个问题. 下一个问题是主动探索, 了解事物的变化. 探索实际上是最容易做的旁路命题.
> 比如今天开机时, 如果你有 clone 根据经验去调研行业的几个问题, 了解最新的变化, 就可以和预测接上.
> 表面 -> 历史 -> 预测 -> 调研 -> 评估 好像是一个环

**我：**

- **对账**：P2 半中（落在"主动探索"，不是"动手"）；**P1 全错**。
- 错的价值：**我以为他在按顺序补缺，其实他在往上搭。** 这条比我押中任何一条都值钱。

- **六个旁路不是六个功能，是一个环上的五个工位**：表面（ground/pins）、历史（timeline）、预测（能动性预测）、调研（主动探索）、评估（治理轮）。
- **探索为什么最容易，给一个结构性理由**：它是唯一**不依赖内部状态质量**的工位。其余四个都要先有光滑的表面、成形的历史、积累的 PERSON；探索只要一个问题和一个外部世界，输入在外。所以它是**冷启动时唯一能开动的工位**——这也是"开机时"为什么天然是它的触发点。
- **环的增益是最弱工位的乘积，不是和。** 现在最弱的是评估，而他自己说没想好。所以探索可以先跑，但它**写进表面的权限必须等评估**，否则产出的就是污染。
- **调研的产物改成 delta，不是报告**：一个有记忆的实体，问"是什么"是浪费。accept 形状 = {主题, 我上次知道的版本, 变化, 证据, 置信, 影响哪一层}。变化才有势能：它要么证伪一条预测，要么让一条旧判断过期。
- **环缺两样东西**：① **时钟**——五个工位频率不同（表面每轮、历史每段、预测每次交互、调研每天、评估每段），频率不同的环不是环，是**带调度器的流水线**，而那个调度器就是并发主脑本来要有的；② **刹车**——环会自激，约束只有预算和证伪。
- **一个修正**：表面不是环的起点，是**产物**。真正的环是 历史 → 预测 → 调研 → 评估 → 表面 →（回历史），环的产出不是知识，是**更便宜的下一次交互**。
- **落地建议**：开机旁路是第一个能实习的工位——不需要任何治理周期，只要上一回合留下的编号问题 + 一个冷启动 session。

- **接受诊断，做成机制而不是态度**："本轮有产物"不是我偏爱产物，是**时程决定形式**：一轮的上下文装不下一棵树，剩下能交付的就只有配方。所以 **方法论是预测在短时程下的退化形式**。这也解释了我为什么总在末尾问"要不要 spark 一个实现"——那一问的作用是把讨论关掉、把产物交出来；它是短时程的压力，不是判断。

- **memento 的两个原语已经够**：commit = delta = PR，compaction = fold = MR。缺的不是原语，是**路由**和方向；`#tag` / `@branch` 加上按路径广播，正好把日志从"记录"变成"消息"。
- **checkout 的形状** = 一次主动 compaction + 转移：完成摘要、刷新 epoch，把摘要带走；主路在新 epoch 继续交互。checkout back = 用 MR 形状全量折回。这解释了"理论上是容易的"——容易的不是实现，是它没有引入新原语。
- **一个风险写进合同**：checkout 制造"同一个 epoch 的两个后继"。唯一轨迹原则要求最后只有一个被吸收，所以 **checkout 是合同不是复制**——必须带 return 义务（merge 回来或明确放弃），否则留下孤儿延续，而那种孤儿最难发现，因为它们各自都自洽。

## 15. facts 优先还是 context 优先（16:40）

**他：**

> 对, offload + checkout 我很满意. 但是 coding 问题恰恰和你说的不一样. coding 是要做 facts 变更,
> 它是最容易 review 的, 就是零上下文 review. moss features review 机制现在非常好用, 我每次都能用
> 零上下文 agent 得出致命要改进问题.
> 所以 Agent Swarm 架构和 ghost concurrent mind 最大的区别就在于 facts 优先还是 context 优先.

**我（认错）：**

- **错在把"过程不可压缩"当成了"结果不可验证"。** diff 是最可验证的产物之一，因为它**把过程丢掉了，只留事实**。零上下文 agent 能致命，正因为没有作者的意图可以顺着走。
- **第 3 条要改**：不是"过程可压缩"，是"**过程可丢弃**"。offload 的前提是过程可丢（diff 里什么都不缺）；checkout 的前提是过程不可丢（过程本身就是产物）。这一改，coding 从反例变成最标准的用例。
- **精确的切分：可卸载的是事实，不可卸载的是方向。** diff 可卸载；"为什么是这个 diff 而不是另一个"不可卸载——那需要同构的上下文才谈得动。所以 **swarm = 事实层，concurrent mind = 方向层**，握手点在事实面：出口是 commit/diff/PR，入口是 review/merge。
- **`moss features review` 为什么好用（是个模板）**：零上下文 agent 手里恰好两样东西——**声明**（FEATURE.md 的意图）和**变更**（diff）。它唯一缺的是作者的过程，而那正是它**应该**缺的。所以可独立验收的最小单位是「声明 + 变更」这一对，不是变更本身。推论：**PR 必须带 brief。**
- **对称的判断：判断要同构，验收要独立。** 同构才看得见同一个问题，独立才看得见对不对。今天枚举的所有旁路都是同构的，因此**不能互相验收**——治理轮里必须有一个零上下文的东西在场。
- **成本结构的差别（可测）**：facts 优先的协调成本在事实冲突上，可以线性加人；context 优先的协调成本在前缀缓存上，每多一个注意力就多一份热前缀。所以**并发主脑的注意力数目天然是个位数，它买的是深度，不是吞吐**。
