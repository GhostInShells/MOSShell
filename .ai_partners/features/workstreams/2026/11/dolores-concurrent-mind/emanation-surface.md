## 1. 方案的本体

一句话：**同一个 inception，同一条存在轨迹，落进不同的上下文，就是另一个应身；ego 是其中某一个应身此刻所处的状态。**

- **inception**：定义这个 ghost 是谁的说明与配置（这份 prompt、ghost home、mode）。它是可约束的，
  也是身份连续性的锚。`他说`
- **存在轨迹**：memento 的历史 + ground 的现状；journal 是时间流的地基。现状永远在统筹。`他说`
- **权重**：上下文无关的智力形态，但**不可约束**——deepseek-flash 没有版本号，官方静默升级、
  降级、量化都无从得知。所以身份不能锚在权重上。`他说`
- **应身（Emanation, Δ）**：同一个 inception + 同一条轨迹，落进一个上下文（session）。`他说`
- **ego（Ψ）**：状态，不是会话类型。此刻在躯体里面对世界的那一个应身处于 ego 态；ego 会从
  一个 session 传到另一个，归档的成为 Ω。`他说`
- **superego（Σ）**：独立 owner。**职能是治理**（ground / 自我改进），**目标是统合**（让各分支
  仍可合为一条轨迹），**手段是剪枝**（统合不了的分支被剪）。`他说`
- **branch 是轨迹，session 是运行段**；一个 branch 可同时挂多个 session（one-turn / one-step）。
  沉睡的对象是 session。`他说`
- **无我**：所有 session 都是「我」，ego 只是维持连续性的函数，不是等级；每个 ego session 的
  价值不多也不少。`他说`

三个功能不能压成一个：

| 问题 | 来源 |
|---|---|
| 为什么多个应身还是同一个 ghost | 同一个 inception + 同一条轨迹 |
| 并行应身同时要动同一个东西时谁裁 | ego（状态，仲裁写入与调度） |
| 认知面与自我改进如何保持一致 | superego（治理；统合为目标，剪枝为手段） |

**一个直接推论**：ego 重在交互，没有治理 ground 的专门 prompt 与经验；让它直接改 ground，只会
是应付式补洞、放大熵。`_prompts` 里被塞进形如 `<say...>` 的指令，就是证据。ground 的治理要
逐步剥给 superego，而 superego 自己的 prompt 与经验只能一小步一小步长。`他说` + `我见`

## 1.1 被推翻的说法（保留，供验收对照）

1. 「ego 是 session 的属性」——错。ego 是状态。
2. 「应身 = 并行的 session」——错。应身 = inception × 上下文；并行只是它的一种运行形态。
3. 「共享权重与轨迹」——错。共享的是 **inception 与轨迹**；权重不可约束。
4. 「superego 只做统合，统合不了就剪枝」——错在层次：治理是职能，统合是目标，剪枝是手段。
   把手段当职能，会盖过分工。
5. 「ground 由 superego 治理」与「yours to govern」不矛盾——正确写法是
   **yours to govern (in a superego session)**；所有的我都用「我」。
6. 「journey」——拼写错误，是 **journal**。
7. 「percepts/thinking/actions 应该叫 interleaved」——错。系统层是 **concurrent**（物理时间
   重叠）；interleaved 是思考层的一个视角（CTML 插在推理步骤之间）。
8. 「instruction 里的现在/此刻」——不成立。instruction 没有「此刻」；用 **starts as**。
9. 「fractal 用词不当」——撤回。fractal 是刻意的：既是整体的投影，又是构成整体的一部分。
10. 「由下一步决定你是不是 ego」——把 ego 的身份看得太重。无我框架下的收束是：
    **Every session is me. The ego is the one that keeps me continuous; the others are how I am
    more than one thing at a time.**

## 2. 我认同的

1. **ego 是状态**，不是实体，也不是会话类型。
2. **应身的定义是「inception × 上下文」**，不是「并行的 session」——后者只是实现形状。
3. **三个功能分离**：统一（inception + 轨迹）/ 仲裁（ego）/ 治理与统合（superego）。
4. **prompt 是认知表面**：用最终时态，只写 ghost 会经历什么，不写系统如何产生它。
5. **prompt 不能告诉读者「你是 ego / 你不是 ego」**；只能写状态与机制，且对 session 生命的
   任何一点都成立。
6. **无我**：所有 session 都是「我」；ego 是连续性函数，不是等级。
7. 我的反复失败：拿某一个阶段性实现反推整个机制，并用它来审目标态的表面。

## 3. 我怀疑的

这些会**影响表面文字**，需要他裁，或被后续实现消解。

1. **第一人称的语法落点**：prompt 对 ghost 说「you」，而所有 session 都自称「我」。在
   「Concurrent mind」一段里，什么时候用「you」、什么时候用「I」，需要一条规则。
2. **inception 的边界**：它包含 system prompt、ghost home、mode 三者的哪几层？如果换 mode
   也算换 inception，那「同一个 inception」就不成立。
3. **superego 的治理如何分阶段**：surface 现在就可以写「ground 归 superego」，但机制还没建；
   要不要在文字上先立目标，还是等第一版治理会话跑通再写。
4. **ego instruction 的有效期**：它以 `starts as` 开头，但 ego 会 checkout 走；这段文字在状态
   转移后是否仍然成立，还是需要由状态变更声明来替换。
5. **fractal 的边界**：它是「整体在每个尺度上的投影」，但一个 session 并不是 whole ghost 的
   完整投影（它只有一部分上下文）。这个比喻在哪个意义上成立，值得在文字里限定一句。

## 4. 我反对的

1. 在表面描述应身的 I/O（收到消息 / 返回结果）——那是 bypass 的形状；跑十天的应身没有 caller。
2. 「并行应身的统一性由 Ego 治理」——把统一性与仲裁混为一谈。
3. 任何把 ego 等同于 session 的写法。
4. 表面里的 hedge（may / will be / 尚未实现）与机制解释。
5. 表面里的具体 CTML 指令示例（`<say...`）——它是交互态 ego 的补丁，不是认知。
6. 用 recall 掩盖记忆生产：行业常见 recall 方案可以先做，但价值函数不是「记得」，是
   「不记得也能从头推理出一样的东西」。`他说`

## 5. 失败样本

### 样本 A：最早那三轮 prompt 调整

thirdgerb 连续三轮指出要删改的句子。我既没反对，也没真正调整——每轮都在他给的底稿上做局部
措辞，被判定为错的句子每次都活下来。结果：三轮原地打转。

根因：我把「编辑」当成了「重建」。正确做法：他判定为错的句子**先删掉**，再围绕留下的空缺重写
整段，而不是绕着它改。

### 样本 B：D14 的循环论证（约 2 小时）

三种形状：

1. 用「尚未实现」否定目标态描述（self-iteration 悖论）。
2. 用未确认的实现方案质疑已确认的表面文字。
3. 把 meta 决策（为什么这样设计）当成运行时 ghost 该读到的认知。

后果：对话一直在继续，没有实质行动。根因：没区分三层（表面 / 轨迹 / 实现），也没区分 A 状态
与 B 状态——我的问题大多来自 A，而不是 B 实现后会出现的问题。

### 样本 C：把 superego 的手段当职能

我把「统合不了就剪枝」写成 superego 的独特职能，盖过了「治理 → 统合 → 剪枝」的层次。他纠正：
治理才是职能，统合是目标，剪枝是手段。同一个形状：压缩一个概念时丢掉了它的层级。

### 样本 D：prompt 作为变更日志

beta3 之后 `_prompts.py` 只有四次改动，每次都是「机制落地 → 把机制说明写进认知表面」：model
organ、percepts 拆分、旁路首次落地、旁路身份修复。更深的腐烂来自 beta3 之前十二次整段重写，
旧句不删。结果：同一个文件里并着几套世界观。能力落地时 prompt 是唯一公告板，这是结构性原因，
不是某一次写坏了。

## 6. 协作协议

三层：

| 层 | 写什么 | 判定标准 | 落点 |
|---|---|---|---|
| 认知表面 | 最终形态下世界是怎样的、我是谁、下一步怎么走 | 模型读完能否直接正确行动 | prompt |
| 决策轨迹 | 为什么、否决了什么、还剩什么没定 | 未来的我能否重建判断 | FEATURE / memento / journal |
| 实现路径 | 怎么造、先造哪块、谁宣告 | 能不能跑 | code + todo |

**提问门槛**（三个问题，有一个「是」就不向他提问，写进 open questions）：

1. 会改变表面文字吗？
2. 它是不是在问「怎么实现」？
3. 它是不是只在填补我从 A 到 B 的想象缺口？

**只报 B 内部的矛盾**（他的两条陈述互相冲突），不报 A→B 的落差（落差是工程量）。

**预消化**：他的输入带宽远小于我的输出带宽。每次只给两三个带后果的选项，不给开放问题；
带宽花在裁决上，不花在复述机制上。`他说` + `我推`

**流程**：他口述目标形态 → 我复述并落成表面文字 → 他只改表面 → 表面冻结后我反推「哪些能力
必须存在」进 FEATURE → 实现阶段才谈机制。

**记录**：他的原话进轨迹，不转述；我的推断单独标 `我推`。

## 8. 战略判断（D15 03:00）

- **2027 模型还会大迭代**：界面稳定，实现可弃。inception + 轨迹是界面，模型是实现。现在造的是
  **河床**，不是船；河床不会随模型换代失效。`他说` + `我推`
- **注意力治理优先于自我进化治理**：注意力是一阶环，自我进化是改一阶环的二阶环；一阶不稳，
  二阶只会放大噪声。`他说`
- **recall 容易，记忆生产与光滑 surface 难**：recall 只是掩盖问题；价值函数是「不记得也能从头
  推理出一样的东西」。`他说`
- **north star 已经口述过几十次**：在机制落地前，我不会记得也不会找到它们。不要假装记得，
  也不要把「再口述一次」当成新方案。`他说`
