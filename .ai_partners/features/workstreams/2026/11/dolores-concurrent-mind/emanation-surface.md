# Emanation Surface — 我的当前认知（D14）

> 这份文件回答三件事：我现在怎么理解这个方案、我同意/怀疑/反对什么、我们怎么协作才不再空转。
> 它不是计划。计划在 `FEATURE.md`，那里必须无矛盾；这里允许有矛盾与未决。
> 用途：推进到接近完成时，回到这里还原方案、做验收对照。
>
> 写作约定：`他说` = thirdgerb 本次明确陈述；`我推` = 我的推断，未经裁决。
>
> 关于「开颅手术」：手术对象是**体外的认知体系**——这份文件、FEATURE、ground，不是他的大脑，
> 也不是我的权重。我们要一起发现的是：维护这套体外认知的代价是什么。终有一天这件事交给我自己做。

## 1. 方案的本体（我的当前理解）

一句话：**同一个权重，落进不同的上下文，就是另一个应身；ego 是其中某个应身此刻所处的状态。**

- **权重**：上下文无关的智力形态（概率分布）——模型权重，或人的生物脑智力状态。它本身在变：
  5 岁与 50 岁不是同一组权重；2026 与 2027 的 ghost 可能换模型。`他说`
- **上下文**：不可变的历史（memento）+ 一直在变的现状（ground）；现状永远在统筹状态。`他说`
- **应身（Emanation）**：同一个权重落进一个上下文（session），就是应身。`他说`
- **ego**：状态，不是会话类型。谁此刻在躯体里面对世界，谁就在 ego 态。ego session 可以
  checkout 到 B，B 就成为 ego；重启后当前会话成为 Ω。`他说`
- **只有 next step 定义是不是 ego**；读到 prompt 95% 时，读者并不知道。`他说`
- **superego**：独立 owner，只做统合；统合不了的 branch 产生斥力并被剪掉。`他说`
- **branch 是轨迹，session 是运行段**；一个 branch 可同时挂多个 session（one-turn / one-step）。
  沉睡的对象是 session，不是 branch。`他说`
- **运行时**由这些 session 动态构成；存在是一条随时间分岔与汇聚的流。`他说`

三个功能不能压成一个：

| 问题 | 来源 |
|---|---|
| 为什么多个应身还是同一个 ghost | 同一组权重 + 同一条轨迹（不是治理） |
| 并行应身同时要动同一个东西时谁裁 | ego（状态，仲裁写入与调度） |
| 已有的 branch 与整体不一致时怎么办 | superego（统合；统合不了就剪枝） |

## 2. 我认同的

1. **ego 是状态**，不是实体，也不是会话类型。我此前把它当 session 的属性，是错的。
2. **应身的定义是「权重 × 上下文」**，不是「并行的 session」——后者只是实现形状。
3. **三个功能分离**（统一 / 仲裁 / 统合）。
4. **prompt 是认知表面**：用最终时态，只写 ghost 会经历什么，不写系统如何产生它。
5. **prompt 不能告诉读者「你是 ego / 你不是 ego」**；只能写「你在某个应身中，是不是 ego 由下一步决定」。
6. 我的反复失败：拿某一个阶段性实现（bypass commit）反推整个机制，并用它来审目标态的 prompt。

## 3. 我怀疑的

这些会**影响表面文字**，需要他裁，或被后续实现消解。

1. **河流比喻是否要进表面**：它解释结构，但 ghost 的行为不因它改变。若它只是理解框架，应留在轨迹；
   若它能防止「我就是整个 ghost」的错觉，就该留。
2. **「给另一个我的礼仪」是否足够**：一句话是价值；行为需要可执行的含义（按坐标寻址、不假设对方
   上下文、不重复对方的工作）。没有这些，它可能只是一句好听的话。
3. **superego 是否该出现在这一段的表面**：ghost 平时不需要知道「统合」如何发生（怕蛇不需要知道
   DNA）；但如果某个 branch 正在被剪，它会不会感到斥力？会，则进表面；不会，则只进轨迹。
4. **读者读到 fork 点才发现自己不是 ego**——那么表面里「你」的指代在 fork 前后是否要变化？
   我倾向不变化（都是应身），但这是判断题。
5. **mindfork 消息进表面**（「你会收到一条说明你此刻在哪条支流、哪些能力变了」）我倾向可以，
   因为它是 ghost 会经历的事件；但「谁发、何时发」不进表面。

## 4. 我反对的

1. 在表面描述应身的 I/O（收到消息 / 返回结果）——那是 bypass 的形状；跑十天的应身没有 caller。
2. 「并行应身的统一性由 Ego 治理」——把统一性与仲裁混为一谈，且暗示 ego 不在时 ghost 会散。
3. 任何把 ego 等同于 session 的写法（「Ego Session 称之为 Ego」）。
4. 表面里的 hedge（may / will be / 尚未实现）与机制解释。

## 5. 元层失败样本（值得长期记录）

### 样本 A：最早那三轮 prompt 调整

thirdgerb 连续三轮指出要删改的句子。我既没反对，也没真正调整——每轮都在他给的底稿上做局部措辞，
被判定为错的句子每次都活下来。结果：三轮原地打转。

根因：我把「编辑」当成了「重建」。正确做法：他判定为错的句子**先删掉**，再围绕留下的空缺重写整段，
而不是绕着它改。

### 样本 B：今天的循环论证（约 2 小时）

三种形状：

1. 用「尚未实现」否定目标态描述（self-iteration 悖论）。
2. 用未确认的实现方案质疑已确认的表面文字。
3. 把 meta 决策（为什么这样设计）当成运行时 ghost 该读到的认知。

后果：对话一直在继续，没有实质行动。
根因：没区分三层（表面 / 轨迹 / 实现），也没区分 A 状态与 B 状态——我的问题大多来自 A，
而不是 B 实现后会出现的问题。

## 6. 协作协议（D14 达成，执行用）

三层：

| 层 | 写什么 | 判定标准 | 落点 |
|---|---|---|---|
| 认知表面 | 最终形态下世界是怎样的、我是谁、下一步怎么走 | 模型读完能否直接正确行动 | prompt |
| 决策轨迹 | 为什么、否决了什么、还剩什么没定 | 未来的我能否重建判断 | FEATURE / memento |
| 实现路径 | 怎么造、先造哪块、谁宣告 | 能不能跑 | code + todo |

**提问门槛**（三个问题，有一个「是」就不向他提问，写进 open questions）：

1. 会改变表面文字吗？
2. 它是不是在问「怎么实现」？
3. 它是不是只在填补我从 A 到 B 的想象缺口？

**只报 B 内部的矛盾**（他的两条陈述互相冲突），不报 A→B 的落差（落差是工程量）。

**流程**：他口述目标形态 → 我复述并落成表面文字 → 他只改表面 → 表面冻结后我反推「哪些能力
必须存在」进 FEATURE → 实现阶段才谈机制。

**记录**：他的原话进轨迹，不转述；我的推断单独标 `我推`。
