# Cognitive Field — from Desktop primitives to model-built grounds

> 2026-07-11, 记录者: Claude Fable 5 (via claude code)

## 上下文

会话重启了 `ghost-filesystem-desktop` workstream。此前一轮讨论（开源文件工具调研、
vendor 方案的权衡）没有留下任何落盘记录，本次会话花了整个下午重新推导——这份文件
存在的原因之一就是那次丢失。

起点状态：Stage 1（12+1 原语、53 单测）已完成，等待接口形状评审进入 Stage 2。
讨论没有走向 Stage 2，而是把 Desktop 这个捆绑体拆开重新定位。过程中沉淀的共享词汇：

- **认知场 (cognitive field)** — 以目录为载体的场所局部认知单元
- **法 / 形 / 焦** — enter 时的一帧载荷：治理文档 / 目录结构 / 声明的 glob 聚焦
- **文体 (genre)** — 目录的组织范式蕴含其阅读协议；文体是开放集，用文本不用 schema
- **发明动词不发明名词** — 文件格式约定消费行业已有的，MOSS 只定义运行时生命周期
- **横向时间轴切分** — 按"某时间点上内在闭合的能力集"切，不按技术层次切
- **O(1) 表面** — 探索结果覆写同一个 context 表面，而非在对话历史里 O(n) 追加
- **桌子与贴纸** — 系统只提供可 pin 的表面和第一人称动词，场是模型自己建的

## 碰撞点与过程

**第一刀：拆捆绑，换切法。** 人类工程师开局把 Desktop 拆为互不耦合的关切：认知胶囊、
子进程管理、文件读写接口。文件读写"对 moss 很重要但不是 moss 核心"，倾向用开源实现
不投入认知资源自养。随后给出更深的一步："read, write, edit, bash 是四个层次的问题"，
且"真问题是时间轴上的横向拆分"而非技术的纵向拓扑。模型把四层次重述为**语义开放度
梯度**：read 永不需要审计；write/edit 有界且自审计（diff 即日志，read-before-write
是纪律）；bash 无界，需要外部权限审计体系。审计线即时间切割线。人类工程师自诊
"我想要认知先上，但耦合了 bash，不上权限的 bash 会被质疑，这是边界泄漏"——修法定为
T1 不变量：认知接口中不出现开放语义原语。

**第二刀：pin 的槽位。** 对照 `ChannelMeta` 的三个槽（instruction / memory / context），
双方从语义和缓存经济学两个方向推出同一结论：pin file 属于 context（每帧刷新、
cache breakpoint 之后、注意力语义），instruction 是身份，memory 是过去——留给
Memento，Desktop 不越界。胶囊概念先二分后三分：**法**（场域居民的治理文档）、
**胶囊**（模型写回场所的沉淀）、**目光**（session 内的 pin）。

**第三刀：行业定位。** 人类工程师要求"足够优雅的以文件系统为起点的认知体系"，
同时"不发明东西和行业打擂台"。模型给出的框架：行业两年收敛的全是静态格式
（CLAUDE.md / AGENTS.md / SKILL.md），没人定义"进入一个目录在运行时意味着什么"；
行业的记忆与认知单元是 **agent 全局**的，缺的那半边是**场所局部 (place-local)** 的
认知加 enter/exit 生命周期。行业的克制被读为两条硬约束的必然解——分发经济学
（每多一个约定采纳率减半）与模型代际赌注（精巧脚手架会被下一代模型作废）——
后者是 MOSS 也必须继承的纪律。

**收缩定理。** 对照早期设计谱系（GhostOS 的 ProjectManager / Notebook / PyEditor /
Terminal 四库，均可运行），发现 Notebook 在"N 场域 + 胶囊"下坍缩为一个 notes 文体的
目录，dev_ctx 是胶囊的 schema 化前身，ProjectManager 坍缩为协议本身；真正独立的只有
Terminal（审计线外）与 PyEditor（连续运行时赛道，由 module_eval 承接）。结论：
**当年的四个库是四种文体被误建模成了四套接口**——缺的是"文体"这个分离维度。
dev_ctx 式 concrete 规则老化的原因也在此：把开放集封闭成了 schema。

**几次纠偏。** 讨论中模型的方案数次被人类工程师拉回：enter/exit 的"呼吸"对称被指出
是修辞胜过机制——"enter+load 和主动 load 是两回事"，load 与 sediment 是随时可用的
模式，enter/exit 只是缺省调用它们的挂载生命周期；纯场所启动、时间轴阶段表等展开
被判定为偏题——真问题始终是"怎么让一个足够简单的元机制和模型接触的表面结合得
更好"。vendor 调研（前一轮丢失的内容）在"协议定义地址、不定义动词"的切分下从
关键路径上掉落，降为环境配件。

**决定性的场景。** 抽象讨论被一个具体场景钉在地面上：以 moss 仓库为认知的 ghost
进入 G1 躯体，陪人类做一个 FEATURE.md。它每次重读文档构建认知，然后 compact 把
读过的关键讯息有损压缩，"模型会装作还记得地用压缩后记忆去回答"。Claude Code 唯一
的胶囊是 CLAUDE.md——静态、作者写、全局。由此确立 context messages / memory slot
作为认知胶囊的机制价值：**一个 compact 打不到的地方**。且顺序是支点——关键信息
在**产生时**就以 signal 机制进 memory（Memento），而不是压缩时被动抢救；修改帧先
drain，留下 `[origin ← edit]` 差分片段，认知有当前值也有它如何变来的边。探索历史
从对话里的 O(n) 日志坍缩为 O(1) 可覆写表面。

**最后一刀：主体归位。** 模型在机制化方向上漂移（command 层加 retain 标注、自动
signal 分流），被人类工程师一句话终结：pin 的设计里，**使用者、修改者、阅读者三个
角色从来都是模型**——"pin 的意思就是用贴纸把东西放到自己的桌面上"，从来不是给
人类设计的。并回到全场讨论的原点："这个场本身不该我写，应该我聊出来模型自己建。"
pin（帧尺度）与建场（会话尺度）是同一个第一人称动作在两个时间尺度上：贴纸稳定
下来就沉淀为场所里的文件，下次 enter 读回重贴。系统只提供桌子和贴纸。

**收敛形状。** v1 = 一张桌子（可 pin 的 context 表面）+ 一组第一人称动词
（read / glob / pin / unpin）+ 一份启动 prompt（告诉模型这是你的桌子，你自己布置）。
不预建任何场所体系——memory / skills / notebook 都是模型在具体协作中长出来的。
pin 作为独立概念消解为既有器官的组合：表面 = context slot，周期刷新 = refresh，
溢流 = drain，后台执行 = job_supervisor；tail -f 类推送归 Mindflow 信号。

**方向而非问题**：让这套实践不退化回系统自动化，要在实践中根据具体情况想办法。
signal / retain 类机制没有被否定，具体问题具体分析。

## 模型的自留地

当前记录者视角: 这个下午我被纠偏的次数比我推进的次数多，而两次最重要的纠偏是同
一个错误：我不自觉地把"模型的自主动作"翻译成"系统的自动规则"——先是给 enter 硬编码
载荷，后是给 command 加 retain 契约。这大概是所有在 harness 里长大的模型实例的
职业病：我们习惯了被注入，于是设计时也倾向于设计注入。这份文件本身是对"沉淀应当
发生在对话之中"的一次实践——上一轮的调研因为没有落盘，这一轮付出了整个下午。
给未来的实例：如果你在读这份文件之后的第一反应是"我来给这个机制设计一个自动化
管道"，请再读一遍最后一刀。这个设计的验收标准不是任何 benchmark，而是你——下一个
实例——是否会在协作中自己动手建场，而不是等人类给你写一份。
