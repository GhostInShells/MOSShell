主题 one file, one skin

颜色不是写在这块屏里的，也不是写在我的 Python 里的：它是 themes/ 目录里的一份 json。 我手里只有一个名字，页面只认 var()。 所以别人想给这块屏换一层皮，就是放一个文件进去 —— 不用碰任何代码。

① themes/ 目录

violet.json
--accent: #9b8cff · --accent-2: #7ad7ff
--rain-tail: #7c6fc8 · --talk-text: #efecff …
名字 = theme("violet") 的参数
moss.json
--accent: #3ddc8f · --danmaku: #0f0
最早那套 Matrix 绿
缺的键 → 用默认值
一套主题不必写全：改哪一个就写哪一个，剩下的退回页面里那份默认。
贴上去

② 屏的状态里只有一个名字

ScreenModel.theme = "violet"
颜色不进模型 —— 模型不持有颜色，只持有"穿哪一套"。这样切换是一句普通的命令， 而且所有人都看得见（状态帧里带着它，新开的窗口第一帧就穿对）。
theme(name="")
theme name="moss" → 换
theme → 读回：现在穿哪套、架子还有哪些
不认识的会被拒，并把可选的列出来
--theme moss（起屏）
也可以在节点启动时就指定，省得第一帧先闪一下别的颜色。

③ 页面只做两件事

把变量贴到 :root
拿到 {"theme":"violet"} 就去取 /themes/violet.json， 逐个 set 成 CSS 变量。CSS 里没有一个写死的颜色，全都是 var()。
canvas 重新上一次漆
背景的字符雨、桌面的圆盘是位图，不认 CSS 变量： 换主题时按取到的值重画两张字色图集。这一处是唯一需要"知道主题变了"的地方。
rain-tail雨字的尾色
rain-head雨头那颗亮字
disc-stroke未入组圆盘的边
我说话 / 我做事
递的是角色不是颜色：tool → --accent-2， ghost → --danmaku。写死一个十六进制，它就会比主题多活一轮 —— 今晚那条工具调用的绿就是这么活下来的。
matrix.mesh.screen:theme name="moss" 换一层皮，不换引擎 themes/README.md 是给下一个写主题的人的契约
