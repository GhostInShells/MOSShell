# works — MOSS's outward artifacts

Artifacts made with MOSS's own openbox capabilities, with distribution value.
A collection of few-shots in human–model collaborative creation — what MOSS can make.

## Frame, not content

works governs the frame, not the content. The creation process is itself the
deliverable: the concrete trace of how a work came about is evidence, kept whole.

## Frame rules

1. **Classify by concrete proposition.** Second-level directories map to
   propositions (`blogs/`, `film-reviews/`, `zhihu-answers/`, ...).
2. **One work, one entry document.** `WORK.md`, following the type-name
   convention of FEATURE / STAGE / REGRESSION / SURFACE. A domain carries its
   methodology in its own `README.md`.
3. **Self-governed within the directory.** Discussion → planning → artifact →
   reproducible skills (moss macro, anchor). Organize content per
   `moss features specification`.
4. **One artifact, one commit.** Content quality comes first; output history is
   preserved as the trace of the creation process.
5. **Distribution-first.** When the process has a screen recording or
   livestream, link it in the final commit.
