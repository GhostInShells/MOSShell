# 主题 / Themes

一块屏的颜色不写在页面里，也不写在 Python 里：它是这里的一份 json。
**做一个主题 = 往这个目录里放一个文件**，不用改一行代码。

```json
{
  "name": "violet",
  "label": "蓝紫 · 住户",
  "description": "一句话说清这套颜色是什么感觉。",
  "vars": { "--accent": "#9b8cff", "--rain-tail": "#7c6fc8", "...": "..." }
}
```

- `name` 必须和文件名（去掉 `.json`）一致 —— 它是 `theme(name)` 的参数。
- `vars` 就是一份 CSS 变量表，页面把它贴到 `:root` 上。**没有的键会退回默认值**
  （`index.html` 的 `:root` 里那份），所以一个主题可以只改两三个变量，先看起来。
- `presence`（可选，默认 `true`）：这套主题里**桌上站着谁**。三种写法：
  - `true` / 不写 —— 用这块屏起屏时配的那个人（`--presence`，或 `presence` 命令）；
  - `false` —— 空桌：人不出现，MOSS 四个字回到正中；
  - `"works/…/someone.html"` —— **这套场景自带化身**：路径按工作区根目录解析，
    换到这套主题时由屏自己把那个页面端上来。别的主题不受影响，换走时桌面上原来
    那个人自动回来。
  一套主题管的是"这一屏长什么样"，不只是几串颜色（2026-10-23 由 thirdgerb 定的：
  原味那套里本来就没有人；化身该属于主题，不属于起屏参数）。
- canvas 那几处（背景字符雨、桌面圆盘）不认 CSS 变量，换主题时页面会重新读一次
  颜色再重画 —— 这一点不需要主题作者操心。

## 最小的一个主题

`vars` 可以整个不写。只声明场景，就等于"默认那套颜色 + 这个场景"：

```json
{ "name": "bare", "presence": false, "vars": {} }
```

放进目录就能 `theme(name="bare")`。**一个 flag 也是一套主题** —— 颜色和场景是同一份
文件里的两组键，各自独立：不写颜色不影响 flags，不写 flag 就继承 `presence: true`。

## 怎么用

```
matrix.mesh.screen:theme name="violet"     # 换；不认识的会报错并列出可选
matrix.mesh.screen:theme                    # 读：现在穿哪套，还有哪些
```

起屏时也可以直接指定：`--theme moss`。

## 现有

| 名字 | 什么感觉 |
|---|---|
| `violet` | 住户身上那身紫；话是紫的、事是冰蓝的，背景压暗一档 |
| `moss` | 屏最早的那一套 Matrix 绿 |

## 键位一览

主色 `--accent` / `--accent-2` / `--accent-3`；文字 `--ink` / `--dim`；
瓷砖 `--tile-*`；侧栏 `--rail-*`；背景雨 `--rain-*`；弹幕 `--danmaku`；
说话那一层 `--talk-*`；名字（MOSS 四个字）`--moss-*`；顶边光带 `--think-*`；
桌面圆盘 `--disc-*`；遮罩 `--mask-*`。

还有三组是 2026-10-23 补的，补的理由是同一条：**它们以前写死在页面里**，
于是紫的屏和绿的屏长着同一副窗框、同一颗"我在不在"的点。

| 组 | 键 | 管什么 |
|---|---|---|
| 窗 | `--win-bg` `--win-bar-a/b` `--win-bar-ink` `--win-name` | 舞台上的窗口：内容底、标题栏、栏里的字 |
| 活着 | `--live-dot` `--live-glow` | 侧栏那颗"我在不在"的点（不跟选中色走） |
| 高光 | `--sheen` `--sheen-strong` `--peek-border` `--peek-pointed` `--page-bg` `--peek-bg` | 细边/细高光/活页底/整页底色 |

缺哪个就用默认值，不必一次写全。
