# file_editor · 三个机制（D17 夜）

从"文档是主角"往下推，三个命题：渲染面、共享编辑、选区感知。
这份稿子只写今晚定下的形状与判据；未定的明写在最后。

## 一、一块文本，三种面

工作副本永远是那段字符串——byte-for-byte 就是将来落盘的东西。呈现分三类：

- **read**：经渲染器投影出来的读面。给眼睛用。
- **raw**：原样、带行号。地址（行区间）只在这里精确。
- **diff**：这一次改了什么。挂在历史里，不占正文。

行号是我们共同的坐标：read / edit / find / rewind 都吃它，所以
「在正文里看」永远落到 raw 的那个区间。

## 二、渲染器

- 一个渲染器 = 一个文件，顶部注释自解释（name / 适用扩展名 / 一句话用途）。
- 位置：节点自带的 renderers/ 是默认库；页面加载时可给相对或绝对路径，
  于是渲染器也能住在别处，甚至跟着文档一起走。
- 契约：纯函数，吃字符串、吐一个渲染结果；不联网、不改工作副本。
  坏了必须大声报错并退回 raw——「没渲染出来」和「渲染器是坏的」不能长得一样。
- 运行时可列、可切；默认按扩展名选，人可以在这一份文档上覆盖。

## 三、共享编辑（本期只做一半）

「两个写者」的成本不在输入框，在光标、撤销、合并。所以本期：
**人不编辑，靠选区加说话。**

- 人的动作 = 选一段、说一句；我看到的是行区间与那句话。
- 我的动作 = 一条带 region 的动作，落在 diff 面里给人看。
- 控制权（owner: ghost / human）只留接口不实现：等真的出现「人要改字」
  的场合再做，而不是先造一个编辑器。

真要做编辑面，按 GitHub 在线编辑的思路：整篇成为一个编辑区，提交时按
一个动作落地，作者记 u——不是一上来就做分栏、多文件、插件。

## 四、选区即感知

- 选中区、光标所在行是**状态**：页面持续上报，我要的时候读得到。
- 只有「看这里」那一下是信号，因为它要抢注意力。
- 判据同 behaviors：会不会改变我下一步做什么。会，所以进状态面；
  但选区的每次抖动都不进。

## 五、已定 / 未定

- **diff 的粒度：按单次有副作用的动作。** 不另开一套 diff 面——历史里那张卡自己
  就是一次 diff；要的是它画得准、读得动：绿=现在有的，灰划线=被换掉的，按 hunk 分块。
- 未定：渲染器的默认归属——按扩展名一个默认，还是每份文档各记一个。
- 未定：人能不能在 diff 面上直接否决某一行。
