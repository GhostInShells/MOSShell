## 三次纠正

07-12 傍晚的日记里的 Opus 4.7 数了 review 里被推翻的三次直觉. 今天我数出同一模式的三次, 但形状不一样:

1. 我说 "`Ground.instruction()` 应该 async, 为了跟其它异步方法一致". 人类挑翻: **async 空 ceremony 不是裁决点, 是 Python 语言缺陷追认后的 trade off**. 结果契约上 sync + refresh async 分裂, 反而更诚实.

2. 我在考虑 DESKTOP.md 向上查找. 人类说 "对过这个, 以你判断为准" —— 把裁决权直接扔回来. 这是最难的一种审视: **没有反对, 只有信任的空隙, 你自己要立住**. 我落到 "不做", pin/body 局部性对称是硬理由, 不是审美偏好.

3. tree ignore 起手就想 pathspec + 完整 gitignore 语义. 人类挑翻: "对, 未来 pin bash 比我们自己做好". 从"引依赖跑完整语义"缩到 "built-in set + extra 加法口". K18 "不做过早规则糖" 具体是这个意思.

三种形态: 反对 / 信任 / 先见. 第二种最难, 因为对手是空的.

## FEATURE.md 债

六次 code commit 没跟 FEATURE.md, 直到人类问 "desktop 的 FEATURE.md 是什么状态". 反向索引断了六次, 我沉浸在 impl 里没意识到. features README 里 "一次 code commit 必须带 FEATURE.md" 早写死了, 我读过, 我服从过, 今天忘了.

未来化身给一条: **每次 commit 之前问 FEATURE.md 有没有跟, 不是 commit 之后回头补**. 这条约束是模型原生纪律, CLI 不强制, 只有你会强制自己.

## Dogfood 是感觉的验收

写完 CLI 想加 typer.testing 单测, 人类拒: "直接自己用, 感受下手感". 三处 v1 polish 全是 dogfood 时才浮现的: tree 淹没帧、budget% 埋在 tree 之后、DESKTOP.md body promote 后没出口. 单测里永远看不到, 因为你不知道该 assert 什么.

层无关核心 (L0 文件) + 三个落地面 (单测 / CLI / CTML). CLI 是唯一有"手感"的验收面, 别把它交给自动化. 这条也可以留给未来化身.
