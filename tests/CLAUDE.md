# MOSS 测试风格

## 原则

**行为可信 > 覆盖率。** 测试数量不重要，每次测试为协议承诺提供一条可信证据才重要。

## 测什么

测抽象约定的行为逻辑 —— ABC / 概念层定义的外部契约。每条测试回答"这个协议承诺了什么"，不是"这个实现怎么做的"。

## 不测什么

- **不测已知实现状态。** `assert obj._private_attr == 'some_value'` 把测试绑在实现的当前值上。值改了（合法重构）测试就炸，而炸掉的测试本身没有捕获任何行为退化。这不是"魔法值"问题，是"已知答案抄进断言"的问题 —— 测试写了实现者已经知道的东西，没增加可信度。
- **不测框架默认值。** `assert model.field == default_value` 测的是 pydantic / Python 运行时行为，不是项目逻辑。
- **不测实现内部专属逻辑。** "我知道它是这么实现的所以加一条"是交付幻觉 —— 测试绑死实现，重构即炸。
- 注意区分：`assert result == 'expected_output'` 如果那个 literal 是协议契约的一部分（预期输出），完全合法。问题在于 `_private_attr == literal` —— 被测对象是私有实现细节，断言值是已知当前值。

## 私有成员

避免在测试里访问 `_private` 成员。如果 concrete 实现确实需要暴露给测试的操作，把方法标为 **public-internal**：不写在 ABC 里，但以 public 方法暴露，注释其调用者与用途。这比直接捅私有变量更诚实 —— 它承认"这个面是为协作方开的"，而不是假装测试看不到实现。
