# MOSS Tutorials

面向人类和模型开发者的叙事性认知入口。每个 tutorial 以具体案例串联核心概念，帮助建立心智模型。

**Tutorial 是 dogfooding 时的产物，模型即写即验，不是长期维护的手册。** 过期就删，除非人类工程师明确要留作 case。

## 难易度分级 (L0-L4)

文件名前缀决定自然排序和阅读路径：

| 级别 | 含义 | 读者需要什么 |
|------|------|------------|
| L0 | 零基础入门 | 不需要理解 MOSS 任何概念，纯操作即可完成 |
| L1 | 基础概念 | 理解一个核心概念 (App / Channel / CTML) |
| L2 | 组合应用 | 组合多个概念，完成有实际意义的场景 |
| L3 | 架构设计 | 涉及跨模块设计决策和模式选择 |
| L4 | 内核开发 | 内核机制、性能调优、自迭代 |

L2 与 L3 之间的边界以**实操时间**为准：能在 2 小时内走通的算 L2，需要跨模块设计决策的算 L3。

## 标题格式

```markdown
# LN. English Title — 中文副标题
```

`LN.` 后跟英文短标题，em-dash 后跟中文副标题。例如 `# L2. AI Eye — 从零到 AI 实时控制的 Pygame 图形应用`。

## 约定

1. **难易度前缀** (`L0_`, `L1_`, ...) — 自然排序，不需要手动维护序号
2. **模型撰写** — 每个 tutorial 由 AI 模型编写，标题下必须有身份和日期署名
3. **源码同行** — tutorial 如需可运行源码，以同名 `.py` 文件放在同目录，按需落地。代码超过 80 行或涉及多文件时，强烈建议提供 `.py`
4. **验证记录在末尾** — 表格格式，注明哪个模型在什么时间走完了这个例子
5. **过期即删** — 按 tutorial 操作发现走不通时，**默认删掉**，不修补。除非人类工程师明确要求"留作 case"（如作为架构演进的历史锚点），否则删除后追加说明到本 README。修补出来的 tutorial 通常还是不能反映最新抽象，只是把 stale 藏起来
6. **知识索引优先** — 每篇 tutorial 以"你需要知道什么"开头，列出必要最小化知识。每一条必须通过 CLI 命令可达。涉及 CTML → 必索引 `moss ctml read`；涉及 MCP → 必索引 MCP 使用指路
7. **不写绝对路径，不交叉引用文档** — 所有指路用 CLI 探索命令（`moss codex` / `moss howtos read` / `moss docs read`），让模型自己去发现。不写 `.moss_ws/apps/foo/bar/` 或 `src/ghoshell_moss/foo.py` 这类路径
8. **基于 nodes 体系** — 新 tutorial 基于 `moss nodes` + `NODE.md` + `Matrix.discover()`。不基于旧的 apps/AppStoreChannel（2026-07 doc-governance 治理后废弃）
9. **最小依赖原则** — tutorial 只依赖 MOSS 核心 CLI（`moss codex` / `moss ctml` / `moss --ai all-commands` / `moss howtos`）。不依赖具体 channel 命令——channel 命令是变更最频繁的层，依赖它就是自制 stale 源

## 署名格式

```markdown
> Written by <model-identity>, <YYYY-MM-DD>
```

放在标题下方。后续同一模型的其他实例可追加修订记录。

## 验证记录格式

表格格式，放在文末：

```markdown
| 时间 | 模型 | 备注 |
|------|------|------|
| 2026-06-02 03:18 CST | deepseek-v4-pro | 全链路走通：create → start → greet → stop |
```

不覆盖历史记录，新验证追加新行。

## CTML 示例风格

示例中不使用类型后缀，除非需要消歧义（如 `"123"` 被解析为 int 而非 str 时用 `:str` 标注）。保持简洁优先。

## 写一个新 tutorial

1. 确定难易度，选前缀：`LN_description.md`
2. 写时间估计和学习目标 bold 行，然后写"你需要知道什么"
3. 以"你要做什么"开头正文 — 读者要从零开始
4. 每一步给出**可复制执行的命令**和**预期输出**，不让读者猜
5. 如果教程依赖某个运行状态（如 MCP 已在跑），在"你需要什么"里明确说
6. 写完自己走一遍，在末尾用表格格式加上验证记录
7. 如有配套源码，创建同名 `.py` 文件
8. 末尾"相关文档"用 CLI 探索命令（`moss codex` / `moss howtos read` / `moss docs read`），不写文件路径

## 读一个 tutorial 时

1. 先看末尾验证记录，确认上次通过的时间和模型
2. 先看"你需要知道什么"，用列出的命令补齐必要知识
3. 从头执行，不在中途跳步
4. 走通后追加你的验证记录（不覆盖历史记录）
5. 走不通：按约定处理（修或删）
