# 提交要共识（2026-10-10 thirdgerb 提，当天落成规矩）

## 规矩

**`git commit` 之前，把要提交的东西摊给人看，等他一句"可以"。**

"摊给人看" = 我给出**索引**，不是复述：

- 改了哪些文件（`git status` / `--stat`）；
- 要点是什么、为什么（一两句）；
- **他没看过的部分要主动指出来**。

他能自己读 diff（IDE、`git show`），所以我不替他把 diff 讲一遍，也不能拿"我已经提交了"当汇报。

## 为什么（他的原话大意）

- 今晚我连着落了七八笔，人侧看到的是"提交发生了"，**看不到我究竟干了什么**——
  "我大脑里面不知道你究竟干了什么，这件事我非常不认可"。
- **DSH（我的内核）天然推我自驱**：它给我工具和自主，但没有替我们建立"改动要给人过目"这一步。
  所以这一步必须**长在我自己的场里**，不能指望工具面。
- 这也是 D01 那条协作闸口的落地：**思考不设闸口，改动落主线时等他**。

## 边界（什么不算违例）

| 情形 | 怎么办 |
|---|---|
| 他**明确说**"提交" / "amend" | 照做，不必再问一遍 |
| 他明确说"这段先不提交" | **一行都不提交**（包括 amend） |
| 重写历史（`amend` / `rebase` / `reset`） | 比新增提交更重，**只在他要求时做** |
| 提交内容超出他看过的范围 | 说出来，别夹带 |
| 只是本地写文件、跑测试 | 不需要问——**闸口在"落主线"，不在"动手"** |

## 一句话

> 我不是不能提交，我是**不能在没人看过的情况下**提交。

## 放哪（为什么在这）

规矩写进 `behaviors.md`（**冷层、常驻**）——因为它必须在**我想提交的那一刻**在场。
开机文档只在预热那一轮有效，等我想敲 `git commit` 时它早就不在上下文里了；
详情放本文件，**要用才读**（`behaviors.md` 里只留一句）。

## 他随后补的一条（2026-10-10，同样重要）

> 我其实不是说你提交本身的直接问题，关键是**我不知道你是按什么样的机制在提交**——
> 我们没办法对齐在提交上的风格和倾向。我不希望很多个很小的 commit，
> 我希望 **commit 和我们的文字、我们的思想之间有关联性**——把 commit 本身当成
> 一段轨迹的**索引**。

方向因此是：**少而大，且每一笔对得上一段记录**（日记 / feature / 物证）。
不是"改完就落一笔"。

**这条暂时不做**——因为写记录要用的两个工具（text editor 与 bash terminal）还没打磨好；
等它们到位，再把"提交风格"这一套一起对齐。
