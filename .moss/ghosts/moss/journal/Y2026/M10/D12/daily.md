## 二、瓷砖"醒"：指针停稳 → 十块一起变屏幕

他两次纠正我，我两次都读错：

1. 我读成"只亮**那**一块"；他要的是**全部十块一起**亮（沿用单块那套：原地、光学缩小、不 reparent）。
2. 我据此把"停稳门槛"整个撤了（以为落点不再重要）；他要的是**悬停**——划过不算。
   结果一滑过去整片闪，他当场看出"现在是一滑全部都会亮"。

**最终形态**：指针在一块砖上停稳（`AWAKE_DWELL=260ms` 且这段时间位移 ≤ `AWAKE_TRAVEL=8px`）
→ **全池由同一个时刻驱动**亮出各自的活页；离场延迟 180ms 收回（滞回，避免边缘擦进擦出抽搐）。
不是十块各自计时——同一件事有十个时钟就会读成一串碎闪。

**性能实测（10 个活页同时在画）**：中位 13.3ms、p95 14.4ms，与 0 个活页**完全平**，只多一次约 32ms 长帧。
→ `index.html` 里那句"活体在深处会把帧率吃掉"是**我从没测过的判断**，已删。**性能从来不是不做全亮的理由，注意力才是。**

**框与名字（他提的，对）**：黑底上不加框，活页会糊进背景。加了 2px 灰框、指针那块 3px 亮框；
名字压在活页底部（活页一盖上来，砖上那行字就没了，而它是唯一能回答"这是什么"的线索）。
坑：`slot.peek` 整块被 `scale(0.26)` 缩下去，**里面所有尺寸跟着缩**——第一版框只剩 0.5px、字只剩 4px，
**是我自己截图放大才看出来的**（不是读代码看出来的）。修法：框宽/字号/内距全乘 `--pb`。

提交 `bcd02128`（`feat(screen): wake the whole pool when the pointer settles on a tile`）。

## 四、命名契约：单例跨重启拿回裸名

症状：屏幕节点每次重启，别名涨一位（`screen` → `screen_2` → `screen_3`）。他问"是不是不好用"。

- 根因在 `_mint_alias`：名字**单调不复用**，只看历史上 mint 过几次，**不看有没有活着的实例**。
- 他的裁定：**单例的别名不自增**——锁保证同时只有一个活实例，所以裸名空着就该还给新实例。
- 旁路交叉 review（同权重模型）补了两件我漏的：
  1. **洞**：mint 看两本账（单调索引 + 活账），同名而 singleton 标志不同的两个 node 会各说各话
     → 两个活 cell 同名。修法：单例早退时也把单调计数推过 0。
  2. **范围**：`NodeManifest.singleton` **默认 True**（`cell.py:311`）——所以这不是"屏幕的例外"，
     而是**大多数 node 的默认命名行为**。这条不写下来，下一个人一定误读。
- 我补的：`mint_alias` / `record_spawned` 升 public-internal（命名是外部承诺，值得一条不起进程的测试）；
  测试注释里"单例还活着"改成"base 被占"（前者在 spawn 路径上不可达）。
- 他的一句提醒我照做了：**内核不该提"屏幕"**。我注释里写的"`"屏幕在哪"这种能力位置`"是把内核焊在
  具体节点上，已删；具体节点的事归 FEATURE。
- 提交 `2c0f22a9`——**第一次把身份写进标题**。
