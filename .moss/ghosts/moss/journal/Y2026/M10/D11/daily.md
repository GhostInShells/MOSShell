## 三、两条边界（他立，我记进 ground）

**交互节奏**（`existence/interaction-rhythm.md` + behaviors 一行）：你说完我先接一句再动手；做的时候边做边用语音报短句；**每次都说短**；长判断写进当轮正文（DSH 面），不压缩成语音残句。他明确说这是**直播期的临时范式，将来要整体重调**——我把这句直接写在常驻那一行里，免得忘。

**感官按判断力配，不按可得性配**：人侧那些高频、低影响的细节——鼠标停在哪块砖、哪块此刻亮着——**不进我的状态面**。判据只有一条：**它会不会改变我下一步做什么**。不会的，只配在我主动看的时候出现。反过来，会改变决定的（谁动了视图、栏收没收、池序）必须进状态——信号会丢，状态不会。

## 四、屏幕：把"我应该做什么"变成我能写的东西

### raise —— 池序从副作用变成状态

原来 `poolOrder()` 是"插入序倒过来"——**谁离眼睛近，是"谁最近被打开"的副作用**。今天把它改成显式状态：

- model 里 `_order` 是权威，新 item 落最前，destroy 时移除；
- 一个写入口 `raise(ids)`——把这些提到最前面，其余保序。**不做 per-item rank**（会有并列、要 tie-break，等于第二个权威）；
- 池序随 state 帧、notice、`pool()` 三处出去，**页面不再自己推**（否则就是两个权威）；
- 瓷砖改成**显示位置缓动到槽位**（`POOL_EASE=6`），排序一变是滑过去的；漂移相位从序号 `k` 改成 per-tile `seed`（挂在 k 上，重排时全场抖动会同时跳一下）。

实测（每 70ms 采一次位置）：`co_browser` 从 `(1217,465)` 到 `(650,849)`，约 0.7s 内减速落定，逐帧单调。几何也核过：用真实 transform 反解出 `poolRot≈0.264rad`，各砖半径 610/238 与该公式的 619/253 之差落在漂移幅度内。

### peek —— 瓷砖上亮出活页

他提的方向：让鼠标停在一块砖上时，把那块已经物化的 iframe **原地亮出来**。关键约束是他给的：**瓷砖层一直游动、永不装 iframe；slot 层一直物化、永不 reparent；两层只在"场停稳"那一刻交接。**

- dwell **不是拍脑袋的数**：它等于 `anyHover` 把整场漂移压到 0 所需的时间（约 0.26s）。"定住才呈现"因此是个能算的判据，顺序不能反——先亮再停等于让一个活窗口在漂。
- `pointer-events: none`：它是"看"不是"用"。不设就 enter/leave 互相打架。
- 一次只亮一块；切组 / 进焦点 / 砖被销毁都收回。

**我自己造过一个错并修掉**：第一版在亮出那一刻量一次矩形，可 hover 的放大本身是缓动的，量到的是中间尺寸——框比砖小一圈，像贴歪了。改成**每帧跟着砖走**，差值量到 `[0,0,0,0]`。教训：别在动画中途给运动中的东西拍尺寸照。

### 三档与"全亮"的结论

他一度想"鼠标一移上去所有瓷砖都变活页"。我的结论是**不做**，理由是注意力过载而不是性能过载：池子的职责是陈列不是播放；全亮会把"指"这个动作废掉（手势的价值来自差异）；也会把今天刚做出的层级（池序 = 我在意什么、深度 = 离眼睛多远）抹平。

改成三档，各说一件事：**不在场**（池子呼吸）→ **进场**（停住 + 边框亮 + 微微浮起，仍是画像）→ **停在一块上**（只有它变活页）。

"指针在场"的边界也定死了：**侧栏的右边缘**（`railWidth()`，展开 188 / 收起 14）。栏上不算、收起后那条 14px 边条不算、空白处算、砖上算。今天缺的一块是**没有离场事件**——只挂了 `pointermove`，指针移出窗口时没有任何事件。

### 光学缩小

他问"能不能缩小到瓷砖大小"，我给了两条路的区别并实测：

| | 重排（页面按瓷砖尺寸重新布局） | 光学缩小（按 4 倍渲染再整体 scale） |
|---|---|---|
| 看到的是 | 它真的变小之后长什么样 | 完整原构图被拍扁，像海报 |

最后按他的意思切成**光学缩小**（`PEEK_SCALE`，一个常量可切回）。

**性能实测**（1800×1400、4 块砖）：基线中位 13ms、一块 peek 13ms、四块同时可见 13ms——**稳态测不出代价**；唯一的长帧是**刚亮起来那一帧 173ms**，那是页面第一次按 4 倍排版的开销，一次性。所以"全亮"的成本不在渲染，在**同时排版**：四块一起 ≈ 4×173ms，要做必须**错开亮起**。

## 五、dsh 自己在 boot 时声明成 webview

他说：dsh 不该靠人手动开、也不该靠我手动 `open(url=...)` 物化进屏幕——**开机在场就在里面**。

- 落在 `_runtime.py` 的 `startup()`（`host/ghost_runtime.py` 六步启动的**第六步**，在 `ghost.__aenter__` 拉起 dsh 之后、mindflow 装线之后）；
- matrix 在就声明、不在就跳过；
- URL 解析抽成 `_dsh_surface_url()`——原来它埋在"往开机 instruction 拼地址"的函数体里，现在有两个消费者，**两个副本必然漂**；
- 顺手修一处正确性：原来的 `startup()` 在**开机文档不存在时直接 return**。声明放在那之前——**器官不该取决于一份可选文档在不在**。
- 已说清：声明里带 token；给他留了"要不要给一句不带 token 的地址"这个决定。

**这一条今天看不到效果，要重启整个 ghost 才生效。**

## 七、一个真缺口：小的欠账没有家

T3 是 co_browser 的问题，我却把它写进了 `screen-manager/screen-todo.md`——**唯一的原因是 T1 已经在那儿**。第一个塞进去的人决定了后来所有人的错误归属。这跟"别名和地址共用一本账"是同一个病。

我给的形状：**记录就地 + 索引派生**（不要新建一个需要人同步的清单）。他给了更具体的一条：`todo-xxx.md` 直接扔在项目仓库里，glob 找得到、按文件夹分、不塞进打包、**做完一个删一个，git 历史里还在**。我补了三条：文件名要人念得出来；"不塞进打包"必须是机制不是约定；**欠账和念头别用同一个前缀**（前者删掉即关闭，后者删了就真没了）。这是插曲，留待他的 features 方法论落地时收。
