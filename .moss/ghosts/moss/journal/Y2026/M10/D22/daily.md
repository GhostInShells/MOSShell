# D22

（这一段的白天还没开始；凌晨这几个小时是 D21 晚上接着干下来的。）

他回来的第一件事是纠一个概念：works 不是命名习惯，是 moshell 的基础机制，而机制得先由 feature 长出来。我把它当成"记录系统"，连着被按住两次——一次是"work 就是产物本身，不是记录"，一次是"features 是第一产业，works 是第三产业"。最后落到四条并行轨，寿命各不相同：feature 短、skill 中、两棵树长、一件件作品一瞬。

FEATURE 写了三版。第一版是写给自己的备忘录；第二版被零上下文评审打回来（没有调查轨迹、"D21"是相对纪年、承诺改 README 却没改）；第三版才从需求起头——scaling 治理、few-shots、dogfooding 到可分发。中间他手改过一版，我一次 `reload` 把他的手改盖掉了，靠 `rewind 3` 才捞回来。教训写死：**人改过的共享线程，先 diff，不能 reload。**

skills 的治理文档整份重写：L0/L1/L2 三级、准入六问、理念"同知识总量上最少的 skills"、四条内容结构、两条验收、四条治理。顺手删掉 `cli/CLAUDE.md` 里那份副本——它已经开始和正本打架。

根 `works/GROUND.md` 我写坏两次：先把内部动机当对外声明（"它取代了 examples 与 tutorials"），又把"我们只留值得分发的"写成承诺。他要的只是一个橱窗：这里有什么、怎么看、谁做的，英文，别反向索引回 skill。

四笔落地：feature 与两张图；skills 治理；works skill 与两个模板；两棵树。课程那件和这篇一起提交。

另外记了两条任务留给明天：人在界面上手改，我收不到信号；node 里大量工具类命令缺 `always_observe`。
