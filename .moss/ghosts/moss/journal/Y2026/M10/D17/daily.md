## 十、一个我自己造的假故障，和取证顺序

直播里要演一个 5-4-3-2-1 倒数，结果每次发出去就报 `UNKNOWN_ERROR: 'int' object is not subscriptable`，一报就把整批命令连同 `say` 一起取消。我先猜是"一次发太多条命令、通道代理扛不住"——这个假说听起来很合理，因为一条能过、三条就炸。

**错。** 真正的 traceback 一直躺在节点日志里（`.moss/runtime/logs/moss.node__webview_screen.log`），我没去读：

```
channel.py line 544, in danmaku
    f"({_dur_txt(duration)}) — {content[:24]}")
TypeError: 'int' object is not subscriptable
```

`content="5"` 被 CTML 的 `literal_eval` 转成整数 5，于是回执那一行的 `content[:24]` 炸了。**命令本身执行得好好的，死在回执上**——所以看起来像"批量出问题"，其实是"数字内容出问题"。修法一行：`content = str(content)`，理由写进注释：一位数的弹幕是很正常的事（倒数就是）。

取证顺序教训写死：**先取 traceback，再建假说。** 今天我为了一个可以一条命令查清的错误，花了十分钟验证一个错误的理论。

## 十二、内核：类型标注从来没有绑定过

直播里连着撞了两次"数字被转成整数"：`content="5"` 让 danmaku 死在 `content[:24]`，`focus(id="2")` 通过了校验却查不到自己。他判：**这是内核级的问题，先补单测把它暴露出来，再修。**

根因比"某个参数没加 type hint"深一层：`parse_function_interface` 用 `inspect.Signature.from_callable(fn)` 建签名，而**所有模块都写着 `from __future__ import annotations`**——于是 `Parameter.annotation` 拿到的是**字符串** `'str'`，不是类型。`prepare_kwargs_by_signature` 里那段按注解绑定判的是 `callable(annotation)`，字符串不可调用 → 整段跳过。**「签名即契约」这句话，在这个仓库里从来没成立过。**

修法：`eval_str=True` 解析注解；解析不出来就回退原始签名（`TYPE_CHECKING` 里的名字不该让整条通道挂掉）；并留一个例外——**真序列交给 `str` 参数时保持原形**，否则 `ids="0,1"`（tuple）会被写成 `"(0, 1)"`，丢掉 `_split_ids` 的解析。

红→绿的证据：把修复 `git stash` 掉之后跑测试，`assert 'int:2' == 'str:2'`；放回去 3 passed。整 `default/ctml` 套件 270 passed，screen 节点 75 passed。

**纪律兑现**：这轮测试是我用 file_editor 写的、经他把 export 卡点过去落盘的；单测在 terminal 卡里跑、他点过。**先红后绿，不是先修后补。**

## 十三、雨停在最后一帧：断线判定按了总线，而不是按角色

他报的问题：打断我的话之后，屏幕上的字符雨不衰减，继续按打断前那个强度往下掉。

**方法**：这次没有先动代码再找理由——先连拍、看图、定位到具体的那个时间戳，再改。

## 十四、file_editor 机制审查（第一遍）

明天要做 stage 2 验收，他点名现在最缺的是 file_editor。我把 863 行页面 + 610 行 channel + 570 行 store 读了一遍，先记问题，不先动手。

1. **导出会覆盖别人刚写的东西**（最危险）：`channel.py:476 _do_export` 直接 `write_text`；`store.open` 只记路径，不记 mtime / size。我开着线程时他若用别的工具改了同一文件，我一次导出就静默盖掉。
2. **NODE.md 与代码矛盾**：文档末段写「after export it is frozen」，而 `store.note_export` 明写「Nothing here ends a thread」——这是 5cab3066 之前的旧说法没跟上。
3. **没有文件大小闸**：`_read_text` 无上限。一个 10MB 的日志会被 read 进我的上下文，也进卡片。
4. **编辑只能"精确片段替换"**：`str_replace` 要求 `old_str` 唯一；大文件或重复片段（多段相同 import）成本高、易错。缺按行编辑。
5. **没有文件内搜索**：命令面没有 find/grep，找一段必须先 read 全文。
6. **live 线程上限是硬错误**：`MAX_LIVE_THREADS = 16`，到顶直接 raise；并行处理多个文件时会把自己卡住，也没有优先级。
7. **`close` 直接丢工作副本**（`_unlink_draft`）：想"先放一放"没有办法，只有崩溃留下的 draft 可恢复。
8. **同一路径不能两版并存**：`open` 里对 path 做唯一校验，"磁盘上的版本 vs 我手上的版本"没法对照。

优先级我给的是：1（数据安全）→ 2（文档）→ 3（上下文安全）→ 4/5（编辑效率）→ 6/7/8（容量与工作流）。等他回来定。

## 十七、编辑器重做：文档成为主角，卡片退成历史

他一句话改了我对 UI 的判断：**线程是文本交互的主角**，卡片可以整个收进 history。于是今晚把 file_editor 从"卡片流 + 详情"重做成三块面。

**形状**：左边线程（名字、路径、版本、动作数、未导出、未读数），中间 document，点卡后在卡下面就地展开，右边那栏撤掉——它和正文抢宽度，空着的时候还什么都不说。页签三个：document / history / meta。meta 收的是"以前每张卡都重复一遍"的那些事实：路径、版本、盘上是第几版、信不信任。

**闸**：`export` 是唯一的副作用动作，它现在长在它说的那份文档上——正文顶上一条横幅，写哪一版、落到哪个文件、[write it] / [not now]；history 里那张卡同步显示同一个闸。卡片上的 ask 输入框删了：跟卡说话就是在跟我说话。

**抽屉**：窄的时候左栏不挤压正文，只留左边一条把手，点它整栏滑出来盖在正文上，带遮罩，选完线程收回。正文的宽度是唯一不能让步的东西。

**diff 的画法**：他给了 Claude Code 作参考。两条行号槽（旧文件、新文件），新增绿底 + 左侧竖条，删除灰字划线，按 hunk 分块。卡片的 effect 页签现在就是 diff，"full" 页签撤了——要看整篇就回正文那一页。

**view 命令**：`view(document|history|meta)`，我可以把页面切到"我正在说的那个面"，页面写明是谁切的；人点页签也会作为状态回报给我。理由是`layout` 那条的延续：呈现归模型，但必须署名。

**未读**：按"动作数"算，不按版本号算——第一版我按版本算，于是 read / find 这类不动版本的动作永远清不掉，他说"点掉了它还不消"。

## 十八、三个命题与今晚定下的判据

1. **渲染器**：文档本质是那段字符串；呈现分三类——read（渲染后的读面）、raw（原样带行号）、diff（这次改了什么）。行号只在 raw 里精确，因为它是我们共同的地址；渲染面用来读，不用来寻址。渲染器是一个文件、顶部注释自解释，放在节点目录里，也可以给相对/绝对路径让它住在别处、跟着文档走；契约是纯函数、不联网、不改工作副本，坏了大方报错并退回 raw。
2. **共享编辑**：本期只做一半——**人不编辑，靠选区加说话**。理由不是省事：打字我比人快，而两个写者真正贵的是光标、撤销、合并。人对一段文字表达的是"这里改成那样"，那正好是选区 + 一句人话，选区就是我已在吃的行号地址。控制权（owner）只留接口。
3. **选区即感知**：选中区与光标行是**状态**，页面持续上报、我要时读得到；只有"看这里"那一下是信号。
