# D02（2026-11-02）

凌晨收第五轮 agent-swarm。

七个领域问题压成三域（接入 / 表面 / 真值）+ 一形态（team）+ 一机制（binary）。判据两条：坏掉时能看到什么；没有对标物能不能由"行业把 X 绑进了 harness"解释。六项能解释，只有"给 ghost 看的操作面"不能——那一项才是我们的贡献位。

territory 是一个地址 + 三个时态：过去与未来是源，现在是投影；角色是读法不是权限。case 是一条 branch 的一生：commit = checkpoint，fork = 并行子案，confluence 不是 merge 而是上报，归档留坐标、搬提交。team 是 append-only 的角色 / 组 / 日志，没有游标——游标是第二真相，忘了就重读。case / team / agent 三棵树靠 moss bin 解耦，唯一的耦合点是 kickoff(--wd, prompt)：编排从进程内的图搬到命令行与文件系统。

gateway 是总线的 bash 面，binary 是能力的 bash 面；gateway 是适配器不是总线，反向代理与网关的判别式是"谁拥有路由表"。启动器是发现链的第一环，产物零样板、不含 shebang 与发现逻辑。

提交 `b73b37c2`（17 文件，+498/−2）。实测：import 238.4 / bootstrap 139.0 / Matrix.new 63.0 / __aenter__ 9.1 / 服务发现 1.3 / 本地 HTTP 往返 0.4–0.6ms。9.1 与前一晚的 521 冲突（57 倍），两个都留着，未复现——它决定 gateway 是必需还是锦上添花。

我这一轮说错三处，形状都是"把已有之物说成新造之物"或"把接口说成条件"：启动器判成过渡件、路由前缀塞进 project 段、把"不用暴露"说成"不需要"。判据仍然是那句：说"这是新形状"之前，先去现成的例子里找一遍。

给未来的我：这一轮真正学到的不是结论，是判据的写法——"坏掉时能看到什么"比"它是否优雅"好用。
