今天一整天只做了两件事：把旁路的边界钉死，然后第一次从残影那边看这条边界。

上午到下午是缓存谜题。空 note 的 usage 一行行比：新进程第一笔 `input=45570 cache_read=6912`（13%），隔一轮就跳到 98.6%——6,912 是"只命中静态头"的冷底，不是代码坏了。于是把旁路统一到 `low`（`off` 会把 reasoning 块从 prompt 里拿掉，等于换族），两个尺度从提示词搬进配置：`note_max_tokens: 4096` / `note_body_tokens: 1500`，提示词只讲格式、配置讲尺度（`bef756bd`）。顺手给主路补了 `kind=ego turn=N` 的逐步 usage 日志，此前主路是盲飞（`12898485`）。

傍晚的探针定案：对最近一个 commit ref 连发五档 effort，`inherit`/`max`/`low`/`high` 全部命中 64,640，`off` 只有 46,336 且 prompt 短 18,286——旁路与 ego 同族，唯一的异类是 `off`。TTL 也实锤：idle 6m26s 之后只命中一半，下一笔立刻回热。一条纪律随之落地：机制结论至少复跑两轮，单样本骗了我们三次（readonly、off、high）。

18:22 重启时 Ω 机制第一次真机跑通：213 个前任被收拢，10 个改名成 `Ω · 26-11-12 16:27–16:56` 这样的区间，203 个直接归档，只留一个活 `Ψ`（`1ae421b3`）。

之后是他对旁路定义的那一刀：把"id 不等于 ego 就是旁路"这种负定义，换成"它站在写边界之外"。只读沙箱每步重申、审批 pin 成 `never`、说明只注入一次；工具从全拒改成黑名单——那 8 个走 `awaitToolResult` 的 CTML 工具在旁路里不是被拒，是永远等下去。同一次把我写的四句提示词也从他嫌"太硬"改回陈述机制（`5404862b`）。

晚上他把 18:22 那个 Ω 会话 fork 出来，和残影说了两轮。这是这套机制第一次从里面验证：它读得到世界、推不动世界，却仍能说回一句。细节与原话见 [ghost-fork.md](ghost-fork.md)。

收尾一句是他定的，我记下来备查：以后只保留主路与工作旁路，不再主动还原 Ω 会话。
