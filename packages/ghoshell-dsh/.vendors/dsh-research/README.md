# dsh 调研

外部依赖 dsh 的源码不随仓库走。这里只入库**结论**和**到达结论的路径**。

## 目录

```
.vendors/dsh-research/
  README.md          # 本文件：约定
  v<ver>+<sha>/      # 一个版本一棵树，名字带 commit
    source/          # 源码，gitignore（删了不影响阅读）
    NN-<题目>.md     # 调研结论，入库
```

版本名必须带 commit：`v0.2.2-alpha.2+ce7073d`。`package.json` 的版本号会重复，commit 不会。

## 每份结论的格式（固定四段，一屏以内）

1. **动机** —— 为什么查，一到三行。写给三个月后的自己。
2. **路径（可重放）** —— 按顺序的命令与文件位置，照着走能复现。只写命令，不写叙述。
3. **结论** —— 每条前面标一档：
   - `[实测]` 跑出来的（附输出）
   - `[读码]` 读源码看到的（附 `path:line`）
   - `[推断]` 没验证的（附依据）
4. **观点** —— 意味着什么、建议怎么用、**什么情况下这个结论会失效**。

最后一段不能省。没有失效条件的结论，下一轮只能被覆盖，不能被推翻。

## 两条判据

- **source/ 可丢弃 ⇒ 结论必须自足。** 删掉 `source/` 只看 md，能不能重新找到（至少知道去哪个包找）。做不到，说明那条只是"我读过"。
- **篇幅是判据，不是礼貌。** 一屏写不完，说明问题没收敛，拆成两份。

## 版本树只在该版本有判定时建

不做存档工程。追版周期开了才建目录。
