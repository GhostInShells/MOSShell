# 00 — swarm 可视化体验纲领（活文档）

> 这份纲领是这次"纯视效体系"的宪法。**每次动手前先读它，改主意也先改这里**，
> 再改代码。产物可以是中间件，纲领不是。
>
> 起草：D28 20:00（moss）。状态：草稿 v1，等 thirdgerb 逐条挑。

## 1. 目标（一句话）

给 MOSS 的 agent swarm 做一套**运行时的纯视效体系**：让人在 3 秒内知道"世界现在长什么样"，
在 30 秒内知道"哪一处值得看"，在 10 分钟内能审计"它凭什么走到这里"。

**验收**：不带任何文字说明，把一个刚开机的人放到这个画面前，他能自己说出三件事——
有几个集群、哪一个在忙、忙的是哪条路径。

## 2. 观众与三档观看

| 档位 | 时长 | 他要什么 | 界面欠他什么 |
|---|---|---|---|
| 路过 | 3s | 整体是否健康、有没有异常 | 一眼的秩序：色温、密度、有没有红点 |
| 停留 | 30s | 谁在跑、跑到哪、下一个卡点在哪 | 可追踪的一条路径 + 呼吸节奏 |
| 审计 | 10min | 凭哪些事实、谁授权的、能不能回放 | 详情面 + 事实出处 + 路径祖先链 |

三档不能共存于同一层：**3s 靠构图，30s 靠动效，10min 靠详情与出处**。

## 3. 认识论：什么算"看到"

- 看得见的是**拓扑与状态**；看不见的是**因果**。因果只在审计档出现，且必须能指到事实（文件/事件）。
- 图上任何一处**动**，都必须能回答"它为什么动"。答不上来就不许动。
- 由此推出两条运动分类（这是整套设计的地基）：
  - **呼吸（ambient）**：不携带任何信息，只表示"还活着"。振幅极小、周期 3–5s、绝不用于编码状态。
  - **事件（event）**：一定有事实来源，一次播放 ≤700ms，播完即静。
  - **判据**：把声音关掉、把事件流停掉，画面仍应缓慢呼吸；如果它死了，说明呼吸被误用成了状态。

## 4. 三层场景与布局提纲

三层不是三个页面，是**同一份数据的三档分辨率**（相机推拉，不是换页）。

### A. 世界 · 集群视图
- 构图：大留白。集群是"细胞"，彼此不连线；留白就是隔离的证据。
- 锚点：每个集群一枚核（Hive），名字在其下方；根目录用小字灰。
- 焦点区：画面中央偏上 60% 是"活动区"；下沿留一条**事实带**（最近落盘的事件摘要，纯文本，一行流）。
- 发现：新集群不是"出现"，是**扫描后显影**（一圈由暗到亮的描边 + 内部点阵依次点亮）。
- 听觉隐喻：无。这里不要声音。

### B. 领地 · 集群内部
- 构图：中心核（Hive/overmind），环绕 workspace（轨道 + 轨迹），下方一块**任务场**。
- 轨道即 overlord：workspace 的轨迹是它被治理的历史，不画成节点。
- 任务场：任务是**格位**，父子用嵌套边界（不是缩进列表），路径用一条贯穿的高亮链。
- 焦点区：任务场左下角放"当前路径"的起点；眼睛从左上进入，顺时针走到任务场。
- 留白规则：核与轨道之间至少留 1.5 倍核半径的空——那是给呼吸的。

### C. 任务 · 实例
- 构图：顶部祖先链（灰、细），中间 op 泳道（每 step 一段），事件弧在上方，资源占位在 op 内部。
- 移动语义：**task 在状态间移动，不是 op 在跑**。op 只是它经过的格。
- 终态：done 收成闭合环；canceled 虚化成断口；exception 留一处缺口并停止呼吸。
- 焦点区：当前 op 是全画面唯一一处"呼吸加快"的地方（周期从 4s 降到 1.6s）——这是唯一的例外，
  因为它就是"注意力在哪"的答案。

## 5. 动效原则

- 缓动：一律 `cubic-bezier(.22,1,.36,1)`（出场）、`cubic-bezier(.4,0,1,1)`（退场）。禁止 linear，除轨道自转。
- 只动 `transform` / `opacity`。绝不逐帧改布局属性。
- 一次只允许**一个**事件动画在播；排队不并发（并发即噪声，噪声即失去可读性）。
- 镜头：三档之间用 800ms 的推拉 + 轻微视差（三层深度：边界 / 核 / 任务场）。
- 静止是设计的一部分：**两次呼吸之间的静，比呼吸本身更重要**。

## 6. 美术细节（起步风格：星辰骨架 + 电路细节）

- 底色：`#060A14 → #0A1224` 径向渐深；叠 2% 噪点（去塑料感）。
- 墨色：`#E6ECFF`；次级 `#8FA0C8`；极弱 `#4A5878`。
- 主色：`#7AA2FF`（冷，结构）；强调 `#FFB86B`（暖，事实/事件）；成功 `#5BE0A0`；异常 `#FF6B8A`。
- 线：结构 1px、远景 0.5px、事件 1.25px 带 8% 外发光。圆润端点，不用纯黑描边。
- 字：系统无衬线，标签字距 `.08em`，数字用等宽/tabular；字号只有三档（10/12/14），层级靠字重与颜色。
- 材质：核有极弱的径向高光；边界环有 1px 内阴影；不使用纹理贴图。
- 构图：舞台留边 ≥8%；右下角常驻一枚极小的"呼吸点"，作为心跳指示（唯一不受"事件"约束的动）。
- 禁：不能像游戏 HUD（血条、小地图、数值面板）；不能出现 emoji；不能用饱和渐变堆砌。

## 7. 交互（这一版只做仿真，不做真数据）

- hover：描边加亮 + 详情面淡入（不位移，避免抖动）。
- click：进入下一档（世界→领地→任务），相机推近。
- 键盘：`1/2/3` 切档，`空格` 暂停/恢复呼吸（给审计用），`R` 重播最近事件。
- ghost 驱动面（草案，将来长成 channel）：`focus(path)` / `highlight(path)` / `play(scene)` / `pause()`。
  原则：**ghost 指，人看**；人也可以自己动，但 ghost 的动作必须可被人的动作打断。

## 8. 性能红线

- 空闲时 0 个 rAF 循环（呼吸用 CSS animation，不用 JS 帧循环）。
- DOM 元素上限 400；超过则切 canvas（这版不触发，但结构上留门）。
- 渲染是**快照的纯函数**：同一份 facts 必须渲染出同一张图（将来 mock/反射出图才有 oracle）。
- 无外部依赖、无字体下载、无动画库。

## 9. 自检清单（每次出图前逐条过）

1. 关掉所有事件动画，画面是否仍在呼吸？
2. 每一个"动"能否指到一条事实？
3. 三档之间推拉是否连贯（不闪、不跳）？
4. 3 秒档：不读字，能否说出"几个集群、谁在忙"？
5. 30 秒档：能否顺着一条路径看到卡点？
6. 审计档：任意一个 op 能否指出它的祖先链与持有者？
7. 换一套色板（电路/极简），语义是否仍然成立？

# 追加（D28 20:2x）— 静息 / 显影双态

> thirdgerb: "按你设计的布局，在交互动作之外，可以有一个纯视觉的展示效果 —— 无语义纯视觉的
> 美学呈现，人类点击时切换到有语义的物化场景。" 这一节把这条落成规则。

## 11. 两个态，义务不同

| | 静息态（ambient） | 显影态（materialized） |
|---|---|---|
| 对谁的义务 | 只对"存在感"和审美 | 对可读、可审计 |
| 回答什么 | 现在**有没有事**（极粗） | 谁在跑、卡在哪、凭什么 |
| 允许出现 | 光、场、呼吸、极少的真事件回声 | 标签、数值、路径、详情、事实 |
| 不允许 | **任何文字与数字** | 装饰盖过信息 |

判据：抬眼一秒、不读任何字，能感到"静 / 在动 / 哪里不对"。

## 12. 切换是不变量上的显影

- **布局是空间记忆，切换不移动任何东西**：两态共用同一套坐标；变的只有注释（标签/数值）、
  连边、和环境动效的振幅（显影后 `--amp` 翻倍 = 呼吸放慢，注意力让给信息）。
- 显影顺序：结构 0ms → 名字 +120ms → 数值 +260ms → 细节（任务格）+400ms。
- 溶解：25s 无交互回静息，**但审计中不睡**（详情开着 / 在某个任务里 / 手动 pin）。
- 静息态不常驻"请点击"：只有鼠标动起来才浮出一行极小提示（意图后显形）。

## 13. 诚实的静息态

- **有位置的动，必须来自真实总量**：核的呼吸周期 = `7.6s − running×1.1s`，是体温计不是装饰。
- **无法用数据解释的动，只能是无位置的场**：星尘、微尘可以生成式漂移，因为没人把它当事实。
- 允许极少量**真事件回声**：一个任务真的完成 → 远处一颗流星。限频（≥45s 一次），宁可少。

## 14. 性能（D28 实测，3000 元素 / 3 秒，Chromium）

| 方案 | fps |
|---|---|
| Canvas2D 逐帧重绘 | **60.3** |
| SVG 逐帧改属性 | **60.2** |
| SVG 3000 个独立 CSS 动画 | 43.5 |
| three.js / WebGL 点云 | 59.3 |

结论：**这个量级 three.js 换不来速度**，它换来的是辉光与体积感，代价是依赖 + 常驻渲染循环。
决定：语义层 SVG（文字锐利、可命中），环境场 Canvas（一次烘焙底图 + 几十个漂移微尘）；
three.js 留到需要体积感的叙事页再评估。空闲降帧、`visibilitychange` 直接停。

## 15. 美术参考（已看过的）

- **戴森球计划（DSP）**：近黑深场 + 一个强光源；细发光线构成结构；点线网络表示"已连接"；
  冷青 + 暖金的双强调（结构=冷，能量/事件=暖）；网格/三角晶格是"有组织的结构"的语汇；
  密度由中心向外衰减。
- **shapez**：浅底 + 深灰传送带 + 高饱和小色块；**流水线即语法** —— 方向箭头、节点图标、
  极小的效率标签；信息密度高但不吵，因为它只画"流"和"节点"。
- **取用**：DSP 给"场与光"，shapez 给"流与节点"。我们的 op 泳道默认走 shapez 的纪律
  （带子 + 节点 + 方向），集群层走 DSP 的场（光晕 + 环 + 点线）。
- 未取用：任何游戏 HUD（血条、小地图、数值面板）、拟物贴图、emoji。

## 16. 现在这一版的取舍（03-ambient.html）

- 静息态只画：星云、极坐标格、核的光、一圈公转的微光、漂移微尘。
- 显影态加：集群名、`N TASKS · M RUNNING`、A 的三个任务格（父子暂不画，等"同图/两图"裁决）。
- 还没做：任务层的显影（点任务进 op 图，沿用 02 的第三档）、动画页。

> 他的原话："把 features 认为是恒星外面的戴森球，swarm 的 hive 是一个施工行星，本质上就是
> 行星上的智能体带着 skill 等飞去恒星这个 workspace 做戴森球开发。"
> 他判定这个原型"超有感觉"，作为**高优候选方案保留**。

## 17. 映射（这是我做的解释，可改）

| 天体 | 对应 | 为什么 |
|---|---|---|
| 恒星 | **workspace**（被建设的那个 repo / 目录） | 一切围绕它长；它自身不随 task 变化 |
| 球壳晶格面 | **feature / workstream** | 壳是围着 workspace 长出来的治理结构；一块面板 = 一条 workstream |
| 六边形面板 | **一个 feature**（绕一个顶点的 6 个三角面） | 比单个三角更像"可施工的单元"，也和 DSP 的语汇对齐 |
| 施工行星 | **hive（swarm 的集群）** | 有工期、有工人、绕着恒星转 |
| 飞行的光点 | **agent 带着 skill 去施工** | 一等公民仍是 task；光点只是"谁在占这个 op" |
| 轨道上的亮弧 | **整体完成度** | 诚实的总量：所有 workstream 的平均进度 |
| 底部标尺 | **时间轴**（2026-05 → 10） | 借的是"仪器感"，不是"仪表盘" |

## 18. 参考（hightopo 的 Solar System，thirdgerb 给的）

看过的三条，已借进原型：
1. **虚线轨道 + 一段亮弧表示进度**：轨道本身是装饰，但那一段弧是数据。→ 我们用它表示整体完成度。
2. **billboard 信息卡**：卡片始终朝向镜头，俯视时自动隐藏，避免糊成一团。→ 我们的做法更保守：
   只在 hover 时把卡片浮在面板上方，不常驻。
3. **flyTo + 右上角选择器**：点击天体推镜头，而不是换页。→ 与 02 的相机推拉一致。
4. 另外借了**底部标尺**：它让"这是一台仪器"的感觉成立，而且不占信息层。

## 19. JS 库调研（可借鉴 / 可采用）

| 库 | 擅长 | 对我们 |
|---|---|---|
| **3d-force-graph**（vasturiano，three.js） | 3D 力导向图、泛光、相机飞行 | 任务图想做成真 3D 网络时首选；引入 three 生态 |
| **Cosmograph / @cosmograph/cosmos**（GPU） | 十万级节点的星系状图 | 只有当我们真的要看上千 op 时才需要；当前 task 图只有几十节点 |
| **sigma.js**（WebGL） | 大规模 2D 图，快 | 备选；视觉偏"图论"，不像星系 |
| **PixiJS** | 2D GPU、粒子、发光 | 环境场（星尘/微尘）如果要更华丽，这是最省的一条路 |
| **three.js + UnrealBloom** | 真辉光、体积感 | 叙事页/动画页值得；主视图不值得（实测帧率相同） |

**当前决定**：主视图继续手写 SVG 投影（零依赖、文字锐利、可被 CTML 精确寻址）；
环境粒子留给 Canvas；three 系只在"要体积感的页面"上出现。
